## YOLO 的基本架构

**一句话理解**：YOLO（You Only Look Once）是[一阶段检测器](/ai-yolo/object-detection-basics#生成候选框-region-proposal-anchor)最经典的代表——不像两阶段检测器那样先用一个专门的网络"海选"候选框，YOLO 把整张图切成一个固定的网格（Grid），让 [CNN backbone](/ai-yolo/cnn-basics#骨干网络-backbone) 一次前向传播直接在每个网格上"吐出"这里有没有物体、框在哪、是什么类别，所以叫"你只看一次"。

```
输入图片 → CNN backbone（卷积+池化，逐层压缩特征图）→ ... → 网格化的特征图 → header（全连接层）→ 输出向量 [Pc, dx, dy, dw, dh, ...]
```

![YOLO 基本架构：CNN backbone + header](/images/yolo_basic_v1.png)

- **CNN backbone**：跟[目标检测的基本步骤](/ai-yolo/object-detection-basics#特征提取-feature-extraction)里讲的完全一样——用一串卷积+池化把原始像素图片逐层压缩成带语义信息的[特征图](/ai-yolo/cnn-basics#特征图-feature-map)，图里蓝色板子越往右越薄，就是尺寸在一路缩小。
- **网格化（Grid）**：backbone 压到最后一层，特征图的空间尺寸变成一个较小的 S×S 网格（图里红/绿/蓝堆叠的小方块），特征图上每一个网格点，都对应原图上的一块区域——这跟[基于卷积的滑动窗口](/ai-yolo/object-detection-basics#基于卷积的滑动窗口-convolutional-implementation-of-sliding-windows)里"特征图每个位置天然对应一个窗口"是同一个原理，YOLO 就是直接拿这个网格当"候选框的位置"用，不用再单独训练一个网络去生成候选框。
- **header（检测头）**：图中红框标出的两层全连接（FC）网络，把网格化的特征图接上去做最后的预测。这一点是 YOLOv1 的标志性设计——从 YOLOv2 开始，header 改成了全卷积结构（不再有 FC 层），所以"FC header"这个画法专指 YOLOv1。
- **输出向量**：`Pc, dx, dy, dw, dh, ...`——`Pc` 是这个网格有没有物体的置信度（Confidence），`dx, dy` 是框中心点相对网格的偏移，`dw, dh` 是框的宽高，省略号后面接的是每个类别的概率，跟前面[分类 + 边界框回归](/ai-yolo/object-detection-basics#分类-边界框回归-classification-bounding-box-regression)里"分类分支 + 回归分支"是同一套东西，只不过 YOLO 把两者拼进了同一个向量，一次输出。

具体数字（对应 YOLOv1 论文在 Pascal VOC 上的原始设置）：

```
输入图片 448×448×3
→ CNN backbone（24 层卷积 + 4 层最大池化，仿 GoogLeNet 结构）→ 输出特征图 7×7×1024
→ 拉平后接 header（2 层全连接）→ reshape 成 7×7×30
```

7×7 就是 S×S 网格（S=7）；每个网格预测 B=2 个框，每个框 5 个数（`Pc, dx, dy, dw, dh`），加上 VOC 的 20 个类别概率：`2×5 + 20 = 30`，正好对上最后 `7×7×30` 的输出尺寸——这也是为什么 YOLOv1 只能在训练时固定网格数和类别数，图片一变（比如换成 COCO 的 80 类）输出层就要跟着重新设计。

跟[两阶段检测器](/ai-yolo/object-detection-basics#生成候选框-region-proposal-anchor)比，YOLO 省掉了"先生成候选框、再分类回归"这两步之间的等待，一次前向传播就出全部结果，所以更快；但因为每个网格只能预测固定数量的框，遇到很多小物体挤在同一个网格里的情况（比如一群密集的鸟），容易漏检——这是 YOLOv1 最大的短板，后续版本（v2 开始引入 anchor、v3 开始多尺度预测）很大程度上就是在补这个洞，后面会展开讲。

图里最后网格化特征图后面接的还是 NMS 之前的原始预测——S×S 个网格、每个网格 B 个框，同一个物体附近还是会有多个网格给出高分预测，最终输出前仍然要跑一遍[非极大值抑制（NMS）](/ai-yolo/object-detection-basics#非极大值抑制-non-maximum-suppression-nms)去重，YOLO 省掉的是"候选框生成"这一步，不是"去重"这一步。

## YOLOv1 的诞生：设计时间、理念与解决的问题

**背景**：YOLOv1 由华盛顿大学的 Joseph Redmon 等人在 2015 年底提出、2016 年发表于 CVPR。在这之前，主流的目标检测方法都是像 Faster R-CNN 这样的[两阶段检测器](/ai-yolo/object-detection-basics#生成候选框-region-proposal-anchor)——先花一步生成候选框，再花一步分类+回归，两步拆开做，速度上不去，很难做到实时。

**一句话理解**：YOLO（You Only Look Once）的核心理念就是名字本身——不像两阶段方法"先圈出候选区域、再逐个细看"，YOLO 把目标检测直接当成一个回归问题（Regression Problem），整张图只看一次（一次前向传播，Single Forward Pass）就直接输出所有物体的位置和类别，中间不需要单独生成候选框。打个比方：两阶段方法像是先在一张合照里用手指把每个可能是人脸的地方圈出来，再一个个凑近了看这是谁；YOLO 是扫一眼整张合照，直接说出"这里是谁、那里是谁"。

**解决了什么问题**：

1. **速度问题（最核心）**：对比前面[两阶段检测器是怎么一步步变快的](/ai-yolo/object-detection-basics#生成候选框-region-proposal-anchor)那张表——Faster R-CNN 约 0.2 秒/图，已经算"接近实时"；YOLOv1 能跑到 **45 FPS**，简化版 Fast YOLO 能到 **155 FPS**，第一次真正把目标检测做到能跟上摄像头视频流的速度。
2. **利用全局上下文（Global Context）**：因为是一次看完整张图，而不是只盯着一个个局部候选框看，网络预测时天然能看到全图信息，比只看局部窗口的方法更少把背景误判成物体。
3. **泛化能力更强（Generalization）**：学的是"整张图 → 物体是什么/在哪"这种更通用的映射，论文里提到它在没见过的画作等分布外图片上表现也比同期方法更稳。

代价是牺牲了一些精度——尤其是小物体、密集物体容易漏检（呼应前面 [anchor 与 IoU](#yolo-的基本架构) 那节提到的短板），这是 YOLOv1 最大的问题，后续版本很大程度上就是在补这个洞。

![YOLOv1 网络架构：24 层卷积 + 2 层全连接](/images/yolo-v1.png)

具体走一遍图里这套结构（原论文用 GoogLeNet 风格设计，不是直接复用 GoogLeNet 预训练权重）：

```
输入 448×448×3
→ 7×7×64 卷积，步长 2 + 2×2 Maxpool，步长 2              → 112×112×192
→ 3×3×192 卷积 + 2×2 Maxpool，步长 2                     → 56×56×256
→ 1×1/3×3 卷积交替 4 层 + 2×2 Maxpool                    → 28×28×512
→ 1×1/3×3 卷积交替 8 层（{1×1×256, 3×3×512}×4）+ Maxpool → 14×14×1024
→ 1×1/3×3 卷积交替 4 层（{1×1×512, 3×3×1024}×2）
  + 2 层 3×3×1024（其中一层步长 2）                       → 7×7×1024
→ 再接 2 层 3×3×1024 卷积                                → 7×7×1024
→ 拉平 → 全连接 4096 → 全连接 → reshape 成 7×7×30
```

数一数总共是 **24 层卷积 + 2 层全连接**，跟前面[YOLO 的基本架构](#yolo-的基本架构)那节"具体数字"里写的"24 层卷积 + 4 层最大池化"对得上——这张图只是把每一层卷积核大小、通道数都具体画了出来。图里反复出现的"1×1 卷积接 3×3 卷积"这个套路，和 [ResNet 的瓶颈块](/ai-yolo/cnn-basics#瓶颈块-bottleneck-block) 是同一个技巧——先用 1×1 卷积把通道数压小，再用 3×3 卷积在压缩后的通道上算，省参数和计算量。最后拉平接的 2 层全连接（尤其是 4096 那一层）也和 [VGG 的全连接头](/ai-yolo/cnn-basics#参数量-比-alexnet-更多-全连接层依然是大头) 一样很吃参数——这正是[前面提到的](#yolo-的基本架构)"从 YOLOv2 开始把 header 换成全卷积"要解决的问题之一。

## YOLO 的输出结构：从列向量到 7×7×60 张量

**一句话理解**：上一节说 header 最后输出一个向量 `[Pc, dx, dy, dw, dh, ...]`，这一节把它拆开讲清楚——这个向量其实是 S×S 个网格、每个网格的预测结果拼在一起的，既可以画成"一堆列向量"，也可以整理成一个三维张量，两种画法信息完全一样，只是形状不同。

![YOLO 输出结构：49 列向量 与 7×7×60 张量](/images/yolo_output.png)

**左边：49 根列向量**

- "49" 这个括号 = 7×7 = 49，对应前面[网格化](#yolo-的基本架构)那节的 S×S 网格（S=7）——**每一列就是一个网格单元（Grid Cell）的完整预测结果**，49 个格子就有 49 列。
- 单独看一列，结构是：

```
Pc, dx, dy, dw, dh   ← 第 1 个 anchor 框：置信度 + 中心点偏移 + 宽高
...                  ← 第 1 个 anchor 框对应的类别概率（图中用省略号代替）
Pc, dx, dy, dw, dh   ← 第 2 个 anchor 框：置信度 + 中心点偏移 + 宽高
...                  ← 第 2 个 anchor 框对应的类别概率
```

也就是这一个网格里预设了 2 个 [anchor](/ai-yolo/object-detection-basics#生成候选框-region-proposal-anchor)，每个 anchor 各自带一整套"有没有物体 + 框在哪 + 是什么类别"，两个 anchor 的结果前后拼起来就是这一整列。

**右边：7×7×60 的立方体**

立方体标了三个数字——7（高）、7（宽）、60（深度/通道数）。这其实就是把左边"49 根竖着的列"重新按图片本来的行列位置摆成 7 行 7 列，每个格子往里凹进去的那根"柱子"长度是 60——**图里那条粉红色高亮的细条，就是左边某一根列向量立起来插进三维格子里的样子**。

具体数字：假设这个场景有 `C` 个类别、每个格子预测 `B=2` 个 anchor，每个 anchor 的向量长度是 `5（Pc+dx+dy+dw+dh）+ C`，两个 anchor 拼起来：

```
2 × (5 + C) = 60
→ 5 + C = 30
→ C = 25
```

如果 `C=25`，每个 anchor 是 `5+25=30` 个数字，两个 anchor 拼起来正好 `30×2=60`，对上了立方体的深度。

一句话总结：**YOLO 网络最后其实是给图片上 S×S 个位置，每个位置输出一条固定长度的向量——这条向量可以横着排成一个 `(49, 60)` 的矩阵（左边画法），也可以按图片本来的行列位置摆成一个 `(7, 7, 60)` 的三维张量（右边画法），代码里 `output.shape` 打印出来就是后一种形式。**

> 这张图用的是"每个 anchor 自己带一份类别概率"的画法（`[Pc,dx,dy,dw,dh,类别...]` 重复 B 次，算出来是 7×7×60）；上一节引用的 YOLOv1 论文原始设计则是"同一个格子里的几个 anchor 共用一份类别概率"（`S×S×(B×5+C)`，VOC 上算出来是 7×7×30）。两种画法在不同教材里都出现过，这里先如实记录，具体该用哪种、`C` 到底是多少，后面再核对确认。

## YOLOv2 的诞生：设计时间、理念与解决的问题

**背景**：YOLOv2 论文《YOLO9000: Better, Faster, Stronger》，还是 Joseph Redmon（这次多了 Ali Farhadi）在 2016 年底提出、2017 年发表于 CVPR，离 [YOLOv1](#yolov1-的诞生-设计时间-理念与解决的问题) 大概一年。"9000" 是因为它后来还能联合训练识别 9000 多个类别，这篇笔记先只看架构改进这部分。

**一句话理解**：YOLOv2 不是推倒重来，而是一条一条去补 YOLOv1 的短板——论文标题的三个词就是三个改进方向：精度要更准（**Better**）、速度要更快（**Faster**）、认识的类别要更多（**Stronger**，这里先不展开）。下面两张图对应的正是 Better 和 Faster 这两块的架构改动。

### 更轻的骨干网络：Darknet-19

![YOLOv2 分类网络架构：Darknet-19](/images/yolo-v2-1.png)

图 1 标题是"YOLOv2-分类网络架构"——Darknet-19 一开始是单独当**图像分类**模型训练的（表格最后几行 `Conv 1000,1×1 → Avgpool Global → Softmax → 1000`，就是在 ImageNet 上做 1000 类分类），练出一个"看得懂图片"的骨干网络后，再把最后这几层分类头去掉、换成检测头去做目标检测——这正是[迁移学习](/ai-yolo/object-detection-basics#迁移学习-transfer-learning)的套路。

对比 [YOLOv1 的 24 层卷积骨干](#yolov1-的诞生-设计时间-理念与解决的问题)，Darknet-19 只有 **19 层卷积 + 5 次池化**，更精简；具体数字：Darknet-19 算一遍前向传播只要约 **55.8 亿次运算**，而 YOLOv1、v2 都用来对比的 VGG-16 要 **306.9 亿次**，差了 5 倍多，精度却差不多。图右侧写的 **CBL（Convolutional Block）= Conv2d + BatchNormalize + Leaky ReLU**，是 Darknet-19 里每一层卷积的标准组合——每层卷积后面都固定接批归一化（[Batch Normalization](/ai-yolo/cnn-basics#批归一化-batch-normalization-bn)），这是 YOLOv1 没有的，论文里光加这一项就把 mAP 提了 2 个多点。骨干网络更轻、训练更稳，直接回应了 v1"精度和速度不能兼得"的问题。

### 跳跃连接（Passthrough）：找回小物体的细节

![YOLOv2 检测网络结构：Darknet + Passthrough + 全卷积输出](/images/yolo-v2-2.png)

图 2 画的是拿 Darknet-19 去做检测的完整流程：`IMAGE → DarkNet（虚线框里就是图 1 那张表的卷积+池化）→ 3 层卷积 → 一个"+"节点 → 再一层卷积 → 输出 classes + boundary boxes`。

关键是那个 **"+"节点**：它不是简单往前传，而是从虚线框内**更早、分辨率更高**的一层（图上从"5 conv max pool"那里拉了根线下来）直接"抄近路"拼接过来，跟最后深层卷积输出的特征图叠在一起，再送进最后的预测层。具体数字：这条近路接的是一张 `26×26×512` 的早期特征图，先按 2×2 的小块重新排列压缩成 `13×13×2048`（每个 2×2 块里的 4 个像素被"拆"到通道维度，空间尺寸缩小、通道数变多，信息不丢），再跟最后一层输出的 `13×13×1024` 在通道方向拼起来，变成 `13×13×3072` 送去做最终预测。

这跟 [ResNet 的跳跃连接](/ai-yolo/cnn-basics#残差学习-跳跃连接-residual-learning-skip-connection) 是同一个思路——只不过 ResNet 是为了解决"网络太深训不动"，这里是为了把**早期分辨率更高、细节更多的特征**也带给最后做预测的那一层，直接针对性解决了 [YOLOv1 小物体容易漏检](#yolov1-的诞生-设计时间-理念与解决的问题) 的老问题。

### 全卷积检测头：告别固定输入尺寸

图 2 最后一步是一层**卷积（conv）**直接输出 `classes + boundary boxes`，全程没有出现"全连接层"——这跟 [YOLOv1 用 2 层全连接（4096 那层）做检测头](#yolov1-的诞生-设计时间-理念与解决的问题) 是本质区别。v2 把整个网络改成了全卷积（Fully Convolutional），好处有两个：一是不用再把特征图拉平塞进固定大小的全连接层，参数量小了很多、跑得更快；二是输入图片分辨率不用再死死绑定某个固定尺寸，训练时可以每隔几个 batch 随机换一次输入分辨率（多尺度训练，Multi-Scale Training），让模型见过大大小小各种尺度，检测各种大小的物体都更稳。

配合这一点，v2 把标准输入分辨率从 v1 的 448×448 换成了 **416×416**——Darknet-19 总共降采样 32 倍（5 次步长为 2 的池化/卷积），`416/32=13`，正好落在一个奇数网格 **13×13** 上（而不是 v1 的 7×7）。用奇数网格是因为它有一个"正中心"的格子：如果物体恰好长在图片正中间，能直接用这一个格子精确框住，不像偶数网格那样中心点被分到 4 个格子的交界处。

（v2 论文里还有一招这两张图没直接画出来——用 k-means 聚类训练集里的真实框尺寸，算出更合理的 [Anchor Box](/ai-yolo/object-detection-basics#生成候选框-region-proposal-anchor) 预设形状，而不是像 Faster R-CNN 那样手工拍脑袋定，这也是前面聊 [Anchor + IoU](#yolo-的基本架构) 时提到的"anchor 负责匹配物体"机制第一次被真正用进 YOLO。）

一句话总结：**YOLOv2 没有换掉"一次看完整张图"的核心思路，而是把骨干网络换轻（Darknet-19 + BN）、把检测头换成全卷积、加了跳跃连接找回细节——三项改动最终让 v2 在 Pascal VOC 2007 上跑到 76.8 mAP、67 FPS（或者更慢一点、78.6 mAP、40 FPS），精度和速度比 YOLOv1 双双上涨，也超过了当时的 Faster R-CNN 和 SSD。**

## YOLOv3 的诞生：设计时间、理念与解决的问题

**背景**：YOLOv3 论文标题就叫《YOLOv3: An Incremental Improvement》（"一次增量式改进"），2018 年 4 月发布，还是 Joseph Redmon + Ali Farhadi，离 [YOLOv2](#yolov2-的诞生-设计时间-理念与解决的问题) 大概一年。

**一句话理解**：YOLOv3 没有发明什么全新的点子，而是把当时业界已经验证好用的技术——ResNet 的残差连接（Residual Connection）、FPN 的多尺度特征融合（Multi-Scale Feature Fusion）——一股脑搬进 YOLO，目标很朴素：在保持"一次看完整张图"这个速度优势的前提下，把 [YOLOv1/v2 对小物体检测不够好](#yolov1-的诞生-设计时间-理念与解决的问题) 这个老短板彻底补上。

![YOLOv3 网络架构：Darknet-53](/images/yolo-v3.png)

### 骨干网络更深更强：Darknet-53

图左边输入 `416×416×3`，经过红框标出的一串 `res1, res2, res8, res8, res4` 走到最深处。这些 `resN` 块对应图下方 **Resblock_body** 的拆解：先做一次 zero padding + 下采样卷积（DBL），再堆 N 个 **Res_unit**——而 Res_unit 的结构（DBL→DBL→add）跟 [ResNet 的残差块/跳跃连接](/ai-yolo/cnn-basics#残差学习-跳跃连接-residual-learning-skip-connection) 是完全一样的思路：输入直接"抄近路"加到两层卷积的输出上。`1+2+8+8+4=23` 个残差单元堆起来，才有了 **Darknet-53** 这个名字——换掉了 [v2 的 Darknet-19](#更轻的骨干网络-darknet-19)，网络更深了，但因为有跳跃连接兜底，不会像普通深层网络那样训不动，精度跟 ResNet-152 相近，速度却快了将近一倍。

图左下角的 **DBL（Darknetconv2D_BN_Leaky）= Conv + BN + Leaky ReLU**，其实就是 [v2 的 CBL 块](#更轻的骨干网络-darknet-19) 换了个名字，本质没变。

### 三尺度预测：从"一次跳跃连接"升级成真正的多尺度融合

图右边骨干网络分出了 **3 条支路**，分别输出 `y1（13×13×255）`、`y2（26×26×255）`、`y3（52×52×255）`：

```
最深层特征（13×13，语义最强，负责测大物体）
  → 直接接 DBL*5 + DBL + conv → y1（13×13×255）
  → 同时接 DBL + 上采样（放大到 26×26）→ 跟骨干网络中间层的 26×26 特征 concat（拼接）
      → DBL*5 + DBL + conv → y2（26×26×255，负责测中等物体）
      → 同时再上采样到 52×52 → 跟更早层的 52×52 特征 concat
          → DBL*5 + DBL + conv → y3（52×52×255，负责测小物体）
```

这个"从深层往浅层不断上采样、再跟浅层细节特征拼接"的结构，就是特征金字塔网络（Feature Pyramid Network, FPN）的经典设计——[v2 的 passthrough](#跳跃连接-passthrough-找回小物体的细节) 只做了"一次"这样的融合、只有一个输出尺度，v3 把它做成了完整的 3 个尺度、层层融合，深层的语义信息和浅层的空间细节被系统性地结合起来，检测小物体的效果明显提升——这也是 v3 被公认"最大提升点"的地方。

具体数字对一下 `255` 是怎么来的：每个尺度预测 **3 个 anchor**，每个 anchor 是 `4 个坐标 + 1 个置信度 + 80 个类别概率（COCO 数据集）= 85`，`3×85=255`，正好对上 `13×13×255`。

> 顺便解开一个前面留的疑问：这个"每个 anchor 自己带一份完整类别概率"的公式 `B×(5+C)`，其实正是从 **v2 开始**就是官方标准写法（v2 论文原文在 VOC 上是 `5×(5+20)=125`），并不是 [v1 原始论文](#yolov1-的诞生-设计时间-理念与解决的问题)"几个 anchor 共用一份类别概率"的 `B×5+C` 写法——这正好解开了前面 [YOLO 的输出结构](#yolo-的输出结构-从列向量到-7×7×60-张量) 那节留下的疑问：`yolo_output.png` 里"每个 anchor 自己带类别概率"的画法，对应的是 v2/v3 的设计，不是 v1。

### 类别预测：从 Softmax 换成独立的逻辑回归分类器

v1/v2 用 Softmax 输出类别概率，隐含假设"一个物体只能属于一个类别"，但现实数据集里经常有重叠标签（比如"人"和"女性"可以同时成立）。v3 把每个类别换成独立的逻辑回归分类器（Logistic Classifier）+ 二元交叉熵损失，天然支持多标签（Multi-label）分类，不再要求类别互斥。

一句话总结：**YOLOv3 靠 Darknet-53（残差连接，网络更深更强）+ 三尺度 FPN 式融合（小物体检测明显变好）+ 独立逻辑回归分类（支持多标签），把 v1/v2 留下的短板逐个补齐，代价是网络变大、速度比 v2 略慢，但依然比同精度的两阶段方法快得多。**

## YOLOv4 的诞生：设计时间、理念与解决的问题

**背景**：YOLOv4 论文《YOLOv4: Optimal Speed and Accuracy of Object Detection》，2020 年 4 月发布，离 [YOLOv3](#yolov3-的诞生-设计时间-理念与解决的问题) 差不多两年。这次作者换了人——Joseph Redmon（v1~v3 的作者）在 2020 年 2 月公开宣布因为担心自己的技术被用在军事、监控等场景，退出了计算机视觉研究；YOLOv4 由 Alexey Bochkovskiy 等人接手，延续同一套 Darknet 开源代码继续做下去。

**一句话理解**：如果说 [v3 是"把好用的招儿搬过来"](#yolov3-的诞生-设计时间-理念与解决的问题)，v4 就是把这件事做到了极致——论文把过去几年目标检测、深度学习训练领域里验证有效的几十种技巧，按"输入、骨干网络（Backbone）、Neck、Head"四个模块分类，一个个做消融实验挨个测试、挑出最优组合。论文标题"Optimal Speed and Accuracy"（速度和精度的最优解）就是目标：而且明确要求整套方案能在**一块普通消费级 GPU**（比如 1080Ti）上训练出来，不需要昂贵的多卡集群——这是比前几代更强调的"可落地、可复现"。

论文还提出了一个贯穿全文的分类框架：

- **Bag of Freebies（免费的午餐）**：只在**训练时**起作用的技巧，不增加推理时的计算量——比如 Mosaic 数据增强、CIoU Loss。
- **Bag of Specials（值得的小投入）**：会给推理增加一点点计算量，但换来明显的精度提升——比如下面要讲的 SPP、PANet、Mish 激活函数。

![YOLOv4 网络架构：CSPDarknet53 + SPP + PANet](/images/yolo-v4.png)

### 骨干网络：CSPDarknet53，减少残差堆叠里的冗余计算

图左边 Backbone 部分是 `CBM → CSP1 → CSP2 → CSP8 → CSP8 → CSP4`，结构分组跟 [v3 的 res1,res2,res8,res8,res4](#骨干网络更深更强-darknet-53) 一一对应，但每组都换成了 **CSP（Cross Stage Partial）** 结构。图左下角拆解了 `CSP X`：输入先过一层 CBM，然后分成两条路——一条走完整的 `CBM → X 个 Res unit → CBM`（该干的活一点没少），另一条直接从前面 CBM 的输出拉一条近路过来（几乎不用算），最后两条路 `Concat` 拼起来再过一层 CBM 融合。这么拆分是为了减少 [v3 那种纯残差堆叠](/ai-yolo/cnn-basics#残差学习-跳跃连接-residual-learning-skip-connection) 里重复的梯度信息，能省下不少计算量，同时训练还更稳。骨干网络里的激活函数也从 Leaky ReLU 换成了 **Mish**（一种更平滑的激活函数），这属于一个 Bag of Specials 的小投入。

### SPP：几乎不加计算量，扩大感受野

Backbone 末端接了一个 **SPP（Spatial Pyramid Pooling）**模块：图左下角画得很清楚，输入并行走 3 个不同窗口大小的 Maxpool，再 Concat 拼起来。这几乎不增加计算量，却能一次性把不同尺度的上下文信息融合进同一张特征图，相当于变相扩大了[感受野](/ai-yolo/cnn-basics#感受野-receptive-field)——对同一张图里有的物体很大、有的很小这种情况更友好。

### Neck：PANet，双向特征融合

图中间标注 **Neck (PANet)**：跟 [v3 的 FPN](#三尺度预测-从-一次跳跃连接-升级成真正的多尺度融合) 只把深层语义"从上往下"传给浅层不同，PANet 在这条路的基础上，又从浅层往深层反向再走一遍（图里能看到两组 `Upsampling → Concat` 之后，紧接着又有一组 `Concat → CBL×5` 往右下走）——把浅层更精细的定位信息也重新汇聚回深层。这样三个尺度最后拿到的特征，既有深层的强语义，又有浅层的强定位，对各种尺寸物体（尤其是大物体的精确定位）都有提升。

具体数字：图里输入分辨率是 **608×608**（比 v3 默认的 416×416 更大），三个输出尺度是 `76×76、38×38、19×19`（`608÷8=76`、`608÷16=38`、`608÷32=19`），每个尺度输出通道是 `(4+1+classes)×3`——跟 [v3 的每个 anchor 自带一份类别概率](#三尺度预测-从-一次跳跃连接-升级成真正的多尺度融合) 是同一个公式，只是最深层的网格从 v3 的 13×13 变成了 19×19（分辨率更大，网格自然更密）。

### Bag of Freebies：靠训练技巧免费提精度

这些模块之外，v4 还在训练阶段加了一批不影响推理速度的技巧，最出名的是 **Mosaic 数据增强**（把 4 张训练图拼成 1 张喂给网络，一张图里就能看到更多物体尺度和背景组合，变相扩大了有效的批大小）和 **CIoU Loss**（比普通 [IoU](/ai-yolo/object-detection-basics#交并比-iou-intersection-over-union) 多考虑了两个框中心点的距离和长宽比，回归收敛更快更准）——这些都是只花训练时间、不花推理算力的"免费"改进。

一句话总结：**YOLOv4 没有再造一个新范式，而是把 CSP（减少冗余计算）、SPP（低成本扩大感受野）、PANet（双向特征融合）这些架构级改进，加上一整套只在训练时起作用的"免费"技巧，系统性地组合到一起——目标是在一块普通 GPU 上就能训出"速度和精度都最优"的检测器，让 YOLO 系列从"能用"进一步做到"好用、好复现"。**

## YOLOv5 的诞生：设计时间、理念与解决的问题

**背景**：YOLOv5 由 Ultralytics 公司的 Glenn Jocher 发布，2020 年 6 月，离 [YOLOv4](#yolov4-的诞生-设计时间-理念与解决的问题) 只隔了两个月。这次背景比前几代都特殊：**v5 没有配套发表学术论文**，只是直接在 GitHub 上开源发布，而且作者跟 v1~v4 的 Darknet 系血统完全没关系——这在当时的 CV 圈子引发了不小的争议（"没论文也敢叫 v5？"）。但更关键的一点是：**v5 是第一个完全用 PyTorch 从零重写的 YOLO**，在这之前 v1~v4 全部基于 Redmon 自己写的 C 语言框架 Darknet。

**一句话理解**：如果说 [v4 是把学术界验证好用的技巧系统性地"集大成"](#yolov4-的诞生-设计时间-理念与解决的问题)，v5 关心的问题完全变了——架构上它并没有比 v4 提出什么新点子（骨干+PANet+多尺度头这套框架基本没变），它真正解决的是"这东西怎么用起来更方便"：换成 PyTorch 意味着能直接 `pip install`、一行命令训练、自动导出到 ONNX/TensorRT 等各种部署格式；同时不再只提供一种模型，而是按网络深度和宽度缩放出 **n/s/m/l/x** 一整个系列，让用户能按自己的算力（从手机到服务器）挑一个合适的速度/精度平衡点。这也是为什么 v5 虽然学术界争议不断，却成了工业界实际用得最多的 YOLO 版本之一。

![YOLOv5 网络架构：Backbone + Neck(PANet) + Head](/images/yolo-v5.png)

**整体结构其实是 v4 的"工程简化版"**：

```
输入 640×640×3
→ Backbone：Conv(64,6,2) → Conv+C3 反复堆叠（128→256→512→1024）→ SPPT
→ Neck：PANet 双向融合（Upsample+Concat 自顶向下，再 Conv(stride2)+Concat 自底向上）
→ Head：3 个尺度输出，对应 80×80、40×40、20×20（640÷8、640÷16、640÷32）
```

三个尺度的网格数跟 [v4 的 76×76/38×38/19×19](#neck-panet-双向特征融合) 是同一个道理——只是 v5 把默认输入分辨率从 v4 的 608×608 又换成了 **640×640**，每一代都在这个数字上小幅调整。

### C3 模块：把 v4 的 CSP 结构简化重命名

图底部拆解了 **C3 = Conv → Bottleneck×n → Concat（跟另一条直接过来的 Conv 支路拼接）→ Conv**——这和 [v4 的 CSP X](#骨干网络-cspdarknet53-减少残差堆叠里的冗余计算) 是同一个思路：分成"一条走完整计算、一条抄近路"两支再拼起来，减少冗余梯度。只是 v5 把它简化成了一个更干净的 PyTorch 模块（3 层卷积的排布，所以叫 C3），整个骨干和 Neck 里反复复用的都是这一个模块，代码更统一、更容易维护。

### Conv 模块：激活函数又换了一次

图底部另一个拆解：**Conv = Conv2d + BN + SiLU**——[v4 用的是 Mish](#骨干网络-cspdarknet53-减少残差堆叠里的冗余计算)，v5 换成了 **SiLU（也叫 Swish）**，效果相近但计算更便宜，属于同一类"用更划算的激活函数换一点点免费精度"的小优化。

### SPPT（SPPF）：功能不变，算得更快

Backbone 末端的 **SPPT**（图上写的应该是 SPPF，Spatial Pyramid Pooling - Fast）跟 [v4 的 SPP](#spp-几乎不加计算量-扩大感受野) 目的完全一样——扩大感受野、融合多尺度上下文——但 v4 是并行跑 3 个不同窗口大小的 Maxpool，SPPF 改成串行复用同一个小窗口 Maxpool 跑 3 次，数学上效果等价，实际算得更快，是典型的"工程优化换速度"的例子。

一句话总结：**YOLOv5 架构上基本是 v4 的延续（CSP 风格骨干 + PANet + 多尺度头），真正的贡献在工程层面——第一次完全用 PyTorch 实现、拆成 n/s/m/l/x 一整个模型家族、训练和部署都做到开箱即用。它解决的不是"检测精度不够"的问题，而是"好架构却难用、难部署"的问题，这也是它能在工业界迅速铺开的最主要原因。**

## YOLOv8 的诞生：设计时间、理念与解决的问题

**背景**：YOLOv8 还是 Ultralytics（Glenn Jocher 团队）出的，2023 年 1 月发布，离 [YOLOv5](#yolov5-的诞生-设计时间-理念与解决的问题) 差不多两年半。跟 v5 一样，v8 发布时也没有配套学术论文，直接开源发布——延续的是同一套"工程优先、快速迭代"的路数。（这中间其实还有 Meituan 的 YOLOv6、原班人马 Chien-Yao Wang 等人的 YOLOv7，都是 2022 年由不同团队发布的，跟 Ultralytics 这条线是平行的分支，这篇笔记先只跟 v5→v8 这条 Ultralytics 自己的脉络走。）

**一句话理解**：[v5 基本没改架构，主要解决好不好用的问题](#yolov5-的诞生-设计时间-理念与解决的问题)；v8 这次是真刀真枪动了检测的核心设计——最大的一刀，是把从 [v2 开始沿用了整整五代的 Anchor Box 机制彻底砍掉](#更轻的骨干网络-darknet-19)，换成 **Anchor-Free（无锚框）**检测。

![YOLOv8 网络架构：Anchor-Free + 解耦头](/images/yolo-v8.png)

### Anchor-Free：不再需要预设形状

图右侧 **Detect** 模块上标着 **AnchorFree**。这是最核心的变化：v2~v5 每次换数据集都要重新[用 k-means 聚类算一遍 anchor 形状](#更轻的骨干网络-darknet-19)，而且[训练时哪个 anchor 负责预测哪个物体，靠的是"IoU 最高者中标"](#yolo-的基本架构)这套机制——本质上是在用一组"预设的猜测形状"去逼近真实物体，猜得准不准很依赖 anchor 选得好不好。v8 把这一步直接砍掉：每个网格点不再对着几个预设形状做微调，而是直接预测"这个点到物体上下左右四条边各有多远"，没有 anchor 形状这个中间概念了，省掉了一整套调参负担。

### TAL：更聪明地分配"谁负责预测这个物体"

图上 Detect 模块还标了 **Assigner: TAL**（Task-Aligned Assigner）。前面提到的["IoU 最高的 anchor 中标"](#yolo-的基本架构)这套规则只看重叠程度，没考虑"这个位置分类预测得准不准"。TAL 把分类置信度和定位质量（IoU）综合算成一个"对齐分数"，用这个分数去挑正样本——分类和定位这两件事的训练目标从此对得更齐，精度更高。

> 这也顺带更新了前面 [YOLO 的基本架构](#yolo-的基本架构) 里 Anchor Box 与 IoU 那部分的内容：那套"anchor+IoU 匹配"的机制是 v2~v7 anchor-based 时代的做法，v8 开始已经换成了 TAL。

### 解耦头（Decoupled Head）：分类和定位分开算

图右下 **Detect** 模块拆得很清楚：Bbox 和 Cls 走的是两条独立的卷积分支——一条一路 `Conv→Conv→Conv2d` 输出 `4×reg_max`（框的坐标）算 **CIoU + DFL** 损失，另一条独立算到 `nc`（类别数）算 **BCE** 损失。v1~v5 里"这是什么"和"框在哪"是共用同一条路径的最后一层输出，但这两个任务真正需要关注的特征并不一样（分类要看纹理/语义，定位要看边缘/位置），挤在一起会互相拖累。拆开各算各的，两边都能学得更专注。

### DFL：坐标预测成一个分布，而不是一个数

Bbox 分支最后用的是 **DFL（Distribution Focal Loss）**：不再让网络直接吐出一个坐标数值，而是把可能的偏移量拆成若干个区间（bin），预测每个区间的概率，再加权算出期望值作为最终坐标——对物体边界本来就模糊（遮挡、糊边）的情况，这样能表达"这里不确定"，比单一数值回归更精细，训练也更容易收敛。

### C2f 模块：比 C3 更丰富的特征复用

中间 **Details** 面板拆开了 **C2f**：输入先 `Split` 成两半，一半直接送到最后 `Concat`，另一半经过一串 **Bottleneck**——关键是每个 Bottleneck 的输出都会一路往后"搭桥"累积到最终的 Concat 里，而不是像 [v5 的 C3](#c3-模块-把-v4-的-csp-结构简化重命名) 那样只在最后拼一次。这么设计梯度和特征流动的路径更丰富（借鉴了同期 YOLOv7 的 ELAN 设计思路），在参数量差不多的情况下能学到更丰富的表示。

具体数字：骨干网络还是 `640×640×3` 输入，一路降采样产出 P1~P5 五级特征金字塔，最后接 [SPPF](#sppt-sppf-功能不变-算得更快)（和 v5 一样）；Neck 部分用 P3/P4/P5 三层做 PANet 式融合，最终还是 `80×80、40×40、20×20` 三个尺度（`640÷8/16/32`），跟 [v4/v5 的网格划分](#neck-panet-双向特征融合) 完全一致——这块没变，变的是每个网格点具体怎么预测。图右边的 `n/s/m/l/x` 模型表，也是延续 [v5 那套按深度/宽度缩放出模型家族](#yolov5-的诞生-设计时间-理念与解决的问题) 的思路，多加了一个 `ratio` 参数微调。

一句话总结：**YOLOv8 是 Ultralytics 在 v5 打好的工程基础上，第一次真正动了检测算法的核心设计——去掉 Anchor、换 TAL 做样本分配、头部拆成分类+定位两条独立分支、用 C2f 和 DFL 提升特征利用率和坐标精度——把 YOLO 系列从"沿用 v2 定下的 anchor-based 范式修修补补"，带进了 anchor-free 时代。**

## YOLO26 的诞生：设计时间、理念与解决的问题

**背景**：**YOLO26** 是 Ultralytics 这条线目前最新的版本，2025 年 9 月 25 日在伦敦的 YOLO Vision 2025（YV25）大会上公布，2026 年 1 月 14 日正式发布，离 [YOLOv8](#yolov8-的诞生-设计时间-理念与解决的问题) 已经三年（中间还有 2024 年的 YOLO11）。命名上直接从"11"跳到"26"，不是编号错误，而是刻意的营销策略——"26" 代表 2026 年，Ultralytics 想把它定位成"2026 年的旗舰模型"，跟苹果把 iOS 版本号直接对齐年份是同一个思路。

**一句话理解**：前几代（尤其 [v8](#yolov8-的诞生-设计时间-理念与解决的问题)）的思路基本是"往模型里加更聪明的结构换精度"；YOLO26 反过来想——真正要优化的是"部署到边缘设备上跑得快不快、稳不稳"，所以能砍的运行时复杂度尽量砍掉（去掉 NMS、去掉 DFL），把提升精度的活儿挪到训练阶段用更聪明的训练方法（MuSGD、ProgLoss、STAL）去补，让最终部署的模型本身尽可能简单、对硬件（尤其是机器人、无人机、手机这类边缘设备）友好——这也是 Ultralytics 官方明确把无人机列为 YOLO26 目标场景之一的原因。

### NMS-Free：彻底做成端到端

从 [YOLO 的基本架构](#yolo-的基本架构) 一路到 v8，最后一步都还要靠 [非极大值抑制（NMS）](/ai-yolo/object-detection-basics#非极大值抑制-non-maximum-suppression-nms) 去重——这一步在不同硬件、不同框架上耗时不稳定，尤其边缘芯片上很难高效实现。YOLO26（延续同门 YOLOv10 率先提出的思路）训练时用两套标签分配同时监督：一套"一对多"负责让模型学得更充分，一套"一对一"专门服务推理——最终部署时只留"一对一"这个分支，直接输出一组不重复的框，NMS 这一步被整个删掉，推理延迟更可控。

### 去掉 DFL：检测头做减法

[v8 引入的 DFL](#dfl-坐标预测成一个分布-而不是一个数) 把坐标预测成一个概率分布，精度是好，但计算和实现更复杂，导出到边缘芯片（NPU、低算力设备）时不好优化。YOLO26 把 DFL 拿掉，换回更直接的回归方式，检测头更简单，靠训练阶段的其他改进把精度补回来。

### MuSGD：训练更稳的混合优化器

YOLO26 引入了 **MuSGD**，把最近大语言模型训练里验证好用的 **Muon** 优化器和传统 **SGD** 结合起来——多维参数（卷积核权重）用两者的混合更新，一维参数（比如 BN 的缩放/偏移）继续用纯 SGD 保持稳定，训练收敛更平滑，n/s/m/l/x 各种规模的模型不用分别精调超参数。

### STAL + ProgLoss：把训练信号补给小物体、对齐推理目标

[小物体容易漏检](#yolov1-的诞生-设计时间-理念与解决的问题) 这个从 v1 就存在、被 v2 的 passthrough、v3 的 FPN、v4 的 PANet 反复修补的老问题，YOLO26 用 **STAL（Small-Target-Aware Label Assignment）** 专门在训练时保证小目标能分到足够多的正样本参与学习，不被大物体"挤占"训练信号。另外还有 **ProgLoss（Progressive Loss）**，让训练过程中的监督信号逐渐向"推理时真正用到的那个头"靠拢，训练目标和部署效果更一致。

![YOLO26 与历代 YOLO 的精度-延迟对比](/images/Ultralytics-YOLO26-Benchmark.jpg)

**图表怎么看**：横轴是延迟（Latency，T4 显卡 + TensorRT10 FP16，每张图片多少毫秒），纵轴是 COCO mAP（精度）。深蓝色这条 YOLO26 曲线（从 26n 到 26x）明显压在其他所有曲线的左上方——同样的延迟下精度更高，或者同样的精度下延迟更低，这种"左上最优"的曲线叫帕累托前沿（Pareto Frontier）。挑两个点对比：`26x` 在延迟约 11.5ms 时精度约 57.5 mAP，旁边 `11x`（上一代旗舰）延迟差不多（约 11.3ms），精度却只有约 54.7 mAP——同样的速度，YOLO26 精度高出近 3 个点。

一句话总结：**YOLO26 不是靠加新的网络结构堆精度，而是反过来做减法——去掉 NMS、去掉 DFL，把检测头做到最简单，同时用 MuSGD、ProgLoss、STAL 这些训练期的聪明办法把精度补回来，目标是做一个"真正适合部署在机器人、无人机、手机这类边缘设备上"的 YOLO，这也是目前 Ultralytics 这条线（v5→v8→11→26）最新的落脚点。**

# 训练与优化神经网络

## Part 1：基础技巧——向量化

### 神经网络的向量化与矩阵化

**一句话理解**：把"一个个神经元分别算、一条条数据分别算"的循环，改写成"一次性的矩阵运算"——数学上结果完全一样，但写法更简洁，跑起来也快得多（因为可以交给 GPU 并行处理），是神经网络实际训练时的标准做法。

这里有**两层**向量化，分别对应不同的"循环"：

#### 第一层：同一层里，多个神经元一起算

假设某一层有 3 个神经元，输入是 2 个特征 x=(2, 3)。不向量化的写法是，每个神经元单独写一次点积：

```
神经元1：z1 = 1×2 + 2×3 + 1 = 9
神经元2：z2 = 0×2 + 1×3 + 0 = 3
神经元3：z3 = 3×2 + (-1)×3 + 2 = 5
```

把 3 个神经元的权重按行摞成一个矩阵 W，偏置摞成一个向量 b：

```
W = [1  2]      b = [1]
    [0  1]          [0]
    [3 -1]          [2]
```

一次矩阵-向量乘法就能同时算出 3 个神经元的结果：

```
Z = Wx + b = [9, 3, 5]
```

这跟[深度学习基础](/ai-yolo/dl-basics)里前向传播图上的 `Z[1]=W[1]a[0]+b[1]` 是同一件事——那张图里的记号，本身就已经是"跨神经元向量化"之后的写法，只是当时没有点破"这为什么算向量化"。

#### 第二层：同一层，多条训练数据一起算

再往前一步：如果不止 1 条数据，而是一个 batch 里有 3 条数据呢？

```
数据1：(2, 3)      数据2：(4, 0)      数据3：(1, 5)
```

不向量化的做法：写一个 for 循环，把上面这套矩阵-向量乘法对 3 条数据各做一遍。向量化的做法：把 3 条数据按**列**拼成一个矩阵 X（2 个特征 × 3 条数据）：

```
X = [2  4  1]
    [3  0  5]
```

Z = WX + b（b 自动广播到每一列），**一次矩阵-矩阵乘法**同时算出 3 条数据在 3 个神经元上的结果：

```
Z = [9   5   12]     ← 每一列，是一条数据在3个神经元上的输出
    [3   0   5 ]
    [5   14  0 ]
```

第 1 列就是刚才单条数据算出的 `[9,3,5]`，第 2、3 列是另外两条数据，全部**一步到位**，而不是循环 3 次分别调用"算一条数据"。激活函数 `A[1]=g(Z[1])` 同理，直接对整个矩阵逐元素求值，不用再逐个元素循环。

#### 为什么要这样做

- **省写法**：不管这层有 3 个神经元还是 3000 个，不管一批数据是 3 条还是 256 条，公式永远是 `Z=WX+b` 这一行，不用为每个神经元、每条数据单独写一行。
- **真正的原因是速度**：`for` 循环里一个个算点积，Python/CPU 是**串行**执行的；矩阵乘法可以交给底层的 BLAS 库或 GPU **并行**执行——同样的计算量，向量化往往快几十到上百倍。这也是为什么训练时"一次用几十到几百条数据一起算梯度"没有想象中那么慢：不是循环几百次，而是一次矩阵乘法整批算完。

> **类比**：不向量化就像工人一件一件用手工敲零件；向量化就像把一整排零件摆好，用一台冲压机"哐"一声一次全部冲压完——做的是同一件事，一个是纯人力串行，一个是机器批量并行。

## Part 2：正则化——防止过拟合

### L2 正则化（L2 Regularization）：防止模型"死记硬背"

**一句话理解**：在代价函数里额外加一项"权重越大、惩罚越重"的惩罚项，逼着模型在"尽量拟合数据"和"权重别太大"之间找平衡——权重越大往往意味着模型对某个特征的反应越剧烈、越容易死记硬背训练集里的细节（也就是[过拟合](/ai-yolo/dl-basics)）。因为惩罚项用的是权重的**平方**，所以叫 **L2** 正则化（也叫**权重衰减，Weight Decay**）。

**公式**：

```
J_reg(w,b) = J(w,b) + (λ/2m) × Σw²
```

- `J(w,b)`：原来的代价函数，衡量"预测得准不准"。
- `(λ/2m)×Σw²`：新加的惩罚项，衡量"权重是不是太大"。
- `λ`（lambda）：正则化强度，训练前人工设定的超参数，`λ` 越大，对大权重的惩罚越狠；`λ=0` 就退化回普通的代价函数。

**具体例子**：回顾[代价函数](/ai-yolo/dl-basics)那节，w=2、b=30 时用 4 条训练房子数据算出 J=475（m=4）。取 λ=10：

```
惩罚项 = (10/(2×4)) × 2² = 1.25 × 4 = 5
J_reg = 475 + 5 = 480
```

如果 w 更大，比如 w=10：

```
惩罚项 = 1.25 × 10² = 125
J_reg = 475 + 125 = 600
```

**权重越大，惩罚跳得越猛**——w 从 2 变到 10（放大 5 倍），惩罚项却从 5 跳到 125（放大 25 倍，因为是平方关系），这就逼着梯度下降不敢让 w 无节制地变大。

**反映到梯度更新上**：多出来的惩罚项也会给梯度公式加一项：

```
∂J_reg/∂w = ∂J/∂w + (λ/m)×w = -3250 + (10/4)×2 = -3250 + 5 = -3245
```

每一步更新时，都会额外"扣掉"一点点和 w 本身成正比的量（`(λ/m)×w`）——这也是"权重衰减"这个名字的由来：不管原始梯度是多少，每一步都在把权重朝 0 的方向轻轻拽一下。

> **和 L1 的区别（顺带一提）**：如果把惩罚项换成权重的绝对值之和 `Σ|w|`，就是 L1 正则化（L1 Regularization）。L1 会把一部分不重要的权重直接压成 0（相当于自动做特征选择），L2 只会把权重压小、很少正好压到 0——实践中 L2 用得更普遍。

#### L2 正则化和过拟合的关系

**核心关系一句话**：[过拟合](/ai-yolo/dl-basics)的模型之所以能把训练集"死记硬背"下来，背后往往是**权重被推到了很大的数值**；L2 正则化通过惩罚大权重，直接掐断了这条"靠夸张的权重硬背数据"的路，让模型没法再那么精确地穿过每一个训练点，但换来的是在没见过的数据上表现更好。

**为什么过拟合总伴随着大权重**：回顾[欠拟合与过拟合](/ai-yolo/dl-basics)那节的例子：4 套训练房子，用一条**高次曲线**硬是穿过每一个点，训练代价≈0，但测试点（面积100㎡）预测出 500 万这种离谱数字。想让一条曲线在训练点之间**剧烈上下摆动**、又要恰好穿过每一个点，数学上必须靠一些**绝对值很大**（正负都有）的系数把曲线"掰弯"——摆动得越剧烈，需要的系数就越夸张。对比一下三种情况的参数量级：

| | 权重量级 | 训练代价 | 测试误差² |
|-|----------|----------|-----------|
| 欠拟合直线（y=1.5x+50） | 小（w=1.5, b=50） | 4406.25 | 3600 |
| 刚好合适（y=2x+30） | 适中（w=2, b=30） | 475 | 约450 |
| 过拟合高次曲线 | 某些高次项系数可能到几百甚至上千 | ≈0 | 57600 |

**权重越极端，曲线就越"扭曲"，也就越可能只是在拟合训练集里的偶然噪声，而不是真实规律。**

**L2 正则化怎么打断这个过程**：在代价函数里加上 `(λ/2m)×Σw²` 之后，那些原本需要冲到几百、上千的系数，会因为**平方关系**让惩罚跟着暴涨（前面例子里 w 从 2 变到 10，惩罚就从 5 跳到 125），变得"划不来"。优化器权衡下来，会主动选一组小得多的系数——曲线被"拉平"，不再剧烈摆动，自然也没法再精确穿过每一个训练点：

```
训练代价：从 ≈0 回升到某个不再是 0 的值（比如几十）
测试代价：从 57600 大幅下降（因为曲线更接近真实趋势，而不是死记住了每个点）
```

**换个更直观的角度看**：假设模型是一个 4 次多项式 `f(x) = w1x + w2x² + w3x³ + w4x⁴ + b`，图中橙色 ✕ 是训练数据，绿色曲线是没加正则化时学出来的模型——为了穿过（或紧贴）每一个训练点，绿色曲线在数据点之间剧烈扭动，是典型的过拟合：

![L2 正则化例子：惩罚 w4 让曲线从过拟合变平滑](/images/l2_regularization_example.png)

如果故意只给 w4 这一项配一个极大的惩罚系数，把代价函数改成：

```
J(w,b) = (1/2m)Σ(f(x)-y)² + 10000×w4²
```

只要 w4 稍微偏离 0，代价就会因为这个 10000 倍的系数而暴涨——梯度下降为了让代价尽量小，会被逼着把 w4 训练得几乎等于 0。w4≈0 之后，`w4x⁴` 这一项基本消失，4 次多项式实际上退化成了一条三次（甚至更低次）的曲线——也就是图中那条更平滑的蓝色曲线：它不再精确穿过每一个训练点，但整体走势更贴近数据的真实趋势，不再有绿色曲线那种夸张的上下摆动。

这其实是把"给所有权重都加一点点惩罚"的思路推到极致的一个直观演示：**惩罚力度越大，对应的权重就越被压向 0，模型的"有效次数"（有效复杂度）也就越低**——这正是 L2 正则化能把一个原本过拟合的复杂模型，"拉回"成一个更简单、更贴近真实规律的模型的直观原理。

**关键点**：模型的架构完全没变（还是那条高次曲线的公式），但因为权重被压小了，它实际表现出来的"有效复杂度"变得像一个简单得多的模型——这正是正则化常被形容为"限制模型有效复杂度"而不是"改变模型结构"的原因。

**λ 本身也要调，不是越大越好**：

- **λ 太小（接近 0）**：惩罚几乎不起作用，还是容易过拟合。
- **λ 太大**：权重被压得过狠，全都趋近于 0，模型退化得比欠拟合的直线还简单粗糙（极端情况下只剩偏置项，变成一条水平线）。
- 实践中和挑学习率 α 类似：在**验证集**上试几个 λ 值（比如 0.001、0.01、0.1、1、10……），选验证集代价最低的那个。

> **类比**：过拟合就像为了让作文"字字押韵"，硬凑了很多生僻的夸张辞藻（大权重）；L2 正则化就像老师说"用词浮夸要扣分"，逼着你换回朴实的表达——文章可能不再句句押韵（训练代价不再是0），但读起来通顺、放到新题目里也照样能写好（测试代价降低）。

### Dropout：随机"关掉"神经元，防止过拟合

**一句话理解**：训练时，每一步都随机"临时关掉"一部分神经元（让它们的输出变成 0），逼着网络不能过度依赖某几个"明星神经元"，每个神经元都必须学会独立有用、不能对着其他特定神经元"抱团作弊"——这是除了 [L2 正则化](#l2-正则化-l2-regularization-防止模型-死记硬背)之外，另一种非常常用的正则化手段。

#### 具体怎么做

假设某一层有 4 个神经元，这一层的激活值（输出）是 `a=[4, 0, 8, 2]`。设 `keep_prob=0.5`（每个神经元有 50% 概率被保留）：

```
第一步：按 keep_prob 随机生成一个 0/1 掩码
r = [1, 0, 1, 0]   ← 1号、3号神经元保留，2号、4号被"关掉"

第二步：逐元素相乘，被关掉的神经元输出直接清零
a_dropped = a × r = [4, 0, 8, 0]

第三步（Inverted Dropout）：把剩下的值除以 keep_prob，做补偿放大
a_dropped = a_dropped / keep_prob = [8, 0, 16, 0]
```

**为什么要"除以 keep_prob"做补偿**：如果不补偿，这一层输出的期望总量会因为丢掉了一半神经元而整体变小，传给下一层的信号规模会不稳定。除以 `keep_prob` 是为了让这一层输出的期望值和不做 dropout 时基本一致——这样测试阶段就完全不用做任何缩放，直接把全部神经元都用上就行，训练和测试的处理方式对称、简单，这就是现在最常用的实现方式，叫 **Inverted Dropout**。

#### 为什么能防止过拟合

每一步训练，随机关掉的神经元组合都不一样，相当于每一步都在训练一个"结构略有不同的小网络"。因为不知道哪个神经元下一秒会被关掉，任何一个神经元都不敢把自己的输出完全"赌"在某几个特定的其他神经元身上（这种互相依赖叫 **co-adaptation**）——逼着每个神经元都要学会自己扛一部分有用的信息，而不是抱团去死记硬背训练集里的细节。

#### 测试阶段：不用 Dropout

预测时，不做任何 dropout，把训练好的完整网络（所有神经元）直接拿来用——因为 Inverted Dropout 已经在训练时做了缩放补偿，测试时不需要再额外处理。

> **类比**：就像一个项目组平时开会，如果每次都点名让几个固定的人随机请假，剩下的人必须能顶上、独立把活干完——这样锻炼出来的团队，不会因为某个"关键先生"缺席就直接瘫痪，每个人的能力都更扎实、更不依赖别人。

#### 和 L2 正则化的关系

两者都是正则化手段、都是为了防止过拟合，但实现思路不同：

| | L2 正则化 | Dropout |
|-|-----------|---------|
| 怎么做 | 代价函数里加惩罚项，压小权重数值 | 训练时随机丢弃一部分神经元 |
| 作用层面 | 数值层面（权重大小） | 结构层面（神经元之间的依赖） |

实践中两者可以同时用，也可以只选一个。`keep_prob` 通常按层单独设置：神经元多、更容易过拟合的层用更小的 `keep_prob`（丢得更狠），神经元少的层用更大的 `keep_prob`（甚至设成 1，即不丢）。

## Part 3：归一化与初始化——让训练跑得更快更稳

### 数据归一化（Normalizing Inputs）：让梯度下降走得更快

**一句话理解**：把原本量纲、数值范围相差悬殊的各个特征（比如"面积"是几十到几千，"卧室数"是 1 到 5），统一缩放成差不多的范围（比如都变成均值 0、方差 1）——这样代价函数的"地形"从一个很扁的椭圆变成接近正圆，梯度下降就能更直接地冲向最优点，收敛快很多，还能用更大的学习率。

#### 具体做法：两步

```
第一步：零均值化——每个特征减去它自己的均值 μ
第二步：归一化方差——再除以它自己的标准差 σ

公式：x_norm = (x - μ) / σ
```

**具体例子**：假设两个训练样本，特征是"面积"和"卧室数"：

```
面积 x1：50, 150（单位：平米）    → μ1=100, σ1=50
卧室 x2：1,  3 （单位：间）       → μ2=2,   σ2=1
```

归一化后：

```
面积：(50-100)/50 = -1     (150-100)/50 = 1
卧室：(1-2)/1 = -1         (3-2)/1 = 1
```

两个特征原本一个是几十到几百的量级，一个是个位数，归一化后都变成了 **-1 到 1** 这个统一范围。

![归一化三步骤：求均值 μ、求标准差 σ、按 x'=(x-μ)/σ 归一化](/images/normalizing_steps.png)

#### 为什么这能让梯度下降变快

如果不归一化，"面积"这种大数值特征对应的权重 w1 只需要很小的变化就能让预测值大幅波动，而"卧室数"这种小数值特征对应的权重 w2 需要很大的变化才有同等影响——反映到代价函数 J(w1,w2) 的等高线图上，就是一个很扁、很狭长的椭圆。梯度下降在这种狭长地形里容易"之字形"来回震荡，只能用很小的学习率、走很多步才能到底部。归一化之后，各特征量级一致，等高线更接近正圆，梯度下降可以直接、大步地冲向最优点。

![归一化前后对比：左边代价函数是狭长的椭圆等高线，梯度下降路径曲折；右边归一化后是接近正圆的等高线，梯度下降能直接冲向中心](/images/normalizing_result.png)

**一个容易踩的坑**：测试集（或者以后真实预测时的新数据）必须用**训练集算出来的那组 μ 和 σ** 去归一化，不能用测试集自己重新算一遍——因为模型是在"训练集的归一化方式"下学出来的权重，测试时必须套用同一套换算规则，否则同一个原始数值归一化后的含义就变了。

> **类比**：如果拿"米"和"毫米"两种单位去比较两个人的身高差和头发丝直径差，数字上会显得头发丝的变化"微不足道"，但其实两者根本不该放在一起比——归一化就是先把所有特征都换算成统一的"标准单位"，这样才能公平地比较、公平地调整。

> **顺带一提**：这里说的是最常用的**标准化 / Z-score 归一化**，另外还有一种叫 **Min-Max 归一化**，是把数值线性压缩到 [0,1] 或 [-1,1] 区间，公式是 `(x-min)/(max-min)`，两种做法目的一样，选哪种看具体场景。

### 权重初始化（Weight Initialization）

**一句话理解**：权重不能全设成一样的值（比如全 0），也不能随手 random 一下就完事——得根据这一层有多少个"输入"来精心选一个合适的数值范围，否则要么网络里的神经元学出来的东西全都一模一样（浪费容量），要么信号在很多层之间传递时越滚越大或越滚越小，训练直接失控。

#### 为什么不能把权重全初始化成 0（对称性问题）

**具体例子**：假设某隐藏层有 2 个神经元，权重和偏置全设成 0，输入 x=(2,3)：

```
z1 = 0×2 + 0×3 + 0 = 0
z2 = 0×2 + 0×3 + 0 = 0
→ a1 = a2 = g(0)   两个神经元输出完全一样
```

反向传播时，两个神经元算出来的梯度 `dW1` 和 `dW2` 因为用的是同一套公式、同一组输入，也会完全一样。于是每一步更新后，两个神经元的权重还是保持一模一样——不管训练多少轮，这 2 个神经元永远在做同一件事，相当于这一层从 2 个神经元"退化"成了 1 个，白白浪费了模型容量。这就是**对称性（symmetry）问题**：打破对称性，必须靠"权重一开始就不一样"。

#### 为什么不能随便"随机"——太大或太小都有问题

如果每一层的权重量级都偏大（比如系统性地大于 1），信号每过一层就被放大一次，经过很多层之后会像滚雪球一样指数级变大：

```
假设 10 层网络，每层权重让信号放大约 1.5 倍：
1.5^10 ≈ 57.7 倍   ← 信号"爆炸"

假设每层权重让信号缩小约 0.5 倍：
0.5^10 ≈ 0.001 倍  ← 信号"消失"，几乎变成 0
```

这就是深度网络里常说的**梯度爆炸 / 梯度消失**问题的根源之一——网络越深，这种逐层放大或缩小的效应就越夸张，训练会变得极不稳定或者慢到几乎学不动。

#### 常见的初始化方法

**核心思路一样**：随机生成权重，但要按"这一层有多少个输入神经元"（记作 `n`）来缩放随机值的范围，输入越多，每个权重就要设得越小。

```
朴素随机初始化：W = 随机数 × 0.01
  → 简单粗暴，固定用一个很小的常数，浅层网络还凑合，深层网络容易出问题（不管 n 多大都用同一个缩放）

Xavier / Glorot 初始化（配 tanh/sigmoid 激活函数）：
  W = 随机数 × sqrt(1/n)

He 初始化（配 ReLU 激活函数，目前深度网络最常用的默认选择）：
  W = 随机数 × sqrt(2/n)
```

**具体例子（He 初始化）**：假设某一层有 100 个输入神经元（`n=100`）：

```
sqrt(2/100) = sqrt(0.02) ≈ 0.141
→ W = 随机数 × 0.141
```

如果换成 10000 个输入神经元：

```
sqrt(2/10000) = sqrt(0.0002) ≈ 0.014
→ W = 随机数 × 0.014，比刚才小了整整 10 倍
```

**为什么要按输入数量缩放**：一个神经元的输出 `z=w1x1+w2x2+...+wnxn+b` 是 n 项加起来的。如果每一项的方差都是常数，n 越大，加总后 z 的方差就越大（大致跟 n 成正比）——为了不让 z 的规模随着"这一层输入多不多"而忽大忽小，就得让每个权重的方差反过来跟 n 成反比（也就是除以 n），这样不管这一层有 10 个输入还是 10000 个输入，z 的整体规模都能保持差不多稳定。

> **顺带一提：到底该选 He 还是 Xavier？** 不是"大部分情况直接用 He"这么绝对，而是**跟着这一层的激活函数走**：用 ReLU/Leaky ReLU 就配 He 初始化，用 tanh/sigmoid 就配 Xavier 初始化。He 比 Xavier 多出来的那个 2 倍，本来就是专门用来补偿 ReLU"负数部分直接归零、相当于砍掉一半神经元"这个特性的；tanh/sigmoid 没有这种"砍一半"的效应，用 He 反而会让方差偏大。只是现在深度网络的隐藏层大多用 ReLU 系激活函数，所以实践中"大部分时候用 He"只是两者恰好配套、而不是一条独立的死规则。

#### 偏置 b 怎么初始化

直接设成 0 就行——对称性问题的根源是"权重一样导致神经元学出一样的东西"，偏置本身不会引发这个问题，所以不需要随机化。

> **类比**：就像组乐队，如果一开始每个乐手弹的音符都完全一样（权重全设成 0），排练多少次大家还是在弹同一个音符，等于只有一个人在弹；如果一开始把每个人的音量都调得离谱地大，合奏一开场就炸锅（梯度爆炸）；调得离谱地小，声音几乎听不见（梯度消失）。好的初始化就像给每个乐手一个"恰到好处、彼此略有差异"的起始音量——既各自能发挥，又不会一开始就失控。

### Batch Normalization（批归一化）

**一句话理解**：前面讲的[数据归一化](#数据归一化-normalizing-inputs-让梯度下降走得更快)只对最开始的输入特征做了一次；Batch Norm 就是把同样的技巧用到网络**每一个隐藏层的输出**上——每经过一层，都把这一层的输出重新拉回到"均值 0、方差 1"附近，这样网络不管多深，每一层收到的信号规模都稳定，不会越往后传越离谱，训练更快更稳。

**具体做法**：对同一个 mini-batch 里、这一层的所有 z 值，算出这个 batch 的均值 μ 和标准差 σ，做 `z_norm=(z-μ)/σ`；然后再乘一个可学习的 `γ`、加一个可学习的 `β`：

```
z_new = γ·z_norm + β
```

`γ`、`β` 是训练出来的参数，让网络自己决定"要不要保留归一化后的规模"，而不是死板锁死在均值 0、方差 1（比如某些激活函数在均值 0 附近其实不好使，网络可以通过学 `γ`、`β` 把它挪回合适的区间）。

**小例子**：某层某 mini-batch 的 z 值是 `[8, 12, 10, 10]`，μ=10，σ≈1.41，归一化后是 `[-1.41, 1.41, 0, 0]`——不管这一层输入本来是 8~12 还是后面某一层变成 800~1200，归一化后都统一落在这个稳定范围，不用担心"层数一深，数值越滚越大或越滚越小"。

> **类比**：就像流水线上每道工序之间都加一道"质检+校准"，不管上一道工序把零件做大了还是做小了，到下一道工序前都先校准回标准尺寸——这样每道工序都能稳定地在同一个尺寸范围内工作，不会因为上游偏差累积而越到后面越离谱。

## Part 4：优化器——加速梯度下降收敛

### 全批量、随机、小批量梯度下降

**核心问题**：代价函数 J 通常是对全部 m 条训练数据的误差取平均。梯度下降每走一步，都要先算出 J 对权重的梯度——但"每一步更新之前，到底拿多少条数据来算这个梯度"，就衍生出下面三种策略。

先用一个具体数据集贯穿讲解：4 套训练房子（面积→价格）：

```
数据1：(50,  150万)
数据2：(80,  220万)
数据3：(120, 310万)
数据4：(160, 380万)     m=4
```

#### 全批量梯度下降（Batch Gradient Descent，BGD）

**一句话理解**：每走一步之前，都用**全部 m 条数据**一起算出梯度（取平均），算准了再更新一次参数。

**具体过程**：更新一次 w、b 之前，要把 4 条数据的误差全都算一遍、取平均梯度，然后才走一步。这意味着**看完一遍全部数据（这叫 1 个 epoch），只更新了 1 次参数**。

**优点**：梯度方向最准确，每一步都严格朝着代价函数下降最快的方向走，代价曲线平滑、单调下降，不会乱跳。

**缺点**：如果 m 很大（深度学习常见几十万到几百万条数据），每走一步都得先过一遍全部数据才能更新 1 次参数——太慢了。比如 m=500 万，走 1 步就要处理 500 万条数据，训练一天可能才走了没几步。

#### 随机梯度下降（Stochastic Gradient Descent，SGD）

**一句话理解**：走另一个极端，每次**只随机挑 1 条数据**算梯度，算完立刻更新一次参数，不等其他数据。

**具体过程**：还是这 4 条数据，先用第 1 条 (50,150) 算出梯度就更新一次 w、b；再用第 2 条 (80,220) 算梯度、再更新一次……4 条数据都用完，参数已经**更新了 4 次**（而不是 BGD 的 1 次）。

**优点**：更新非常频繁，看一条用一条，不用等；数据量大时，按实际耗时算反而收敛得更快。

**缺点**：

- 只用 1 条数据估计出来的梯度很不准（这条数据可能恰好是噪声或离群点），参数更新路径会很"抖"，代价曲线上蹿下跳，不是平滑下降的。
- 快接近最优点时也很难精确停下来，会在最优点附近一直小幅震荡（除非配合学习率衰减，训练后期把学习率调小）。
- 每次只算 1 条数据，等于退化回了"逐条循环"，没法用[矩阵向量化](#神经网络的向量化与矩阵化)一次性并行处理一批数据，浪费了 GPU 的并行计算优势。

#### 小批量梯度下降（Mini-batch Gradient Descent）

**一句话理解**：折中方案——每次用一小撮数据（不是 1 条，也不是全部），比如 32、64、128 条，算一次梯度就更新一次参数。

**具体过程**：还是 4 条数据，设 mini-batch size=2，先把数据打乱分成 2 组：`{数据1, 数据3}` 和 `{数据2, 数据4}`。先用第一组 2 条数据算平均梯度、更新一次参数；再用第二组 2 条数据算平均梯度、再更新一次。看完一遍全部数据（1 个 epoch），**更新了 2 次**（= m / batch_size = 4/2）。

**优点**：

- 比全批量更新更频繁——不用等全部数据都算完才走一步，训练更快。
- 比随机梯度下降更稳——因为是好几条数据的梯度取平均，噪声被互相抵消了一部分，更新路径没那么抖。
- 能用上矩阵向量化——一个 mini-batch 内的所有数据可以拼成一个矩阵，一次矩阵运算并行算完，比 SGD 逐条算快得多，这也是实践中深度学习几乎清一色都用 mini-batch 的原因。

**代价**：mini-batch size 本身变成了一个新的、需要调的超参数——batch 太小就越接近 SGD（噪声大）；batch 太大就越接近 BGD（慢）。实践中常取 32、64、128、256 这类 2 的幂（对内存对齐、GPU 并行更友好）。

#### 三者对比（还是这个 m=4 的例子）

| | 每次用多少条数据 | 1 个 epoch 更新几次参数 | 梯度准不准 | 更新路径 |
|-|-|-|-|-|
| 全批量 BGD | 全部 4 条 | 1 次 | 最准 | 平滑、单调下降 |
| 随机 SGD | 1 条 | 4 次 | 最不准，噪声大 | 剧烈抖动，最优点附近来回震荡 |
| 小批量（batch=2） | 2 条 | 2 次 | 中等 | 略有抖动，整体仍平滑 |

**放到真实规模上感受一下差异**：假设 m=500 万，batch size=1000：

```
全批量：走 1 步 = 过完全部 500 万条数据          → 1 个 epoch 只更新 1 次
小批量：走 1 步 = 只过 1000 条数据               → 1 个 epoch 更新 5000 次
随机：  走 1 步 = 只过 1 条数据                   → 1 个 epoch 更新 500 万次（但每步噪声极大）
```

数据量越大，"每步只看一部分数据"带来的更新频率优势就越明显——这也是为什么 mini-batch 是深度学习里事实上的默认选择，很少有人在大数据集上真的用纯 BGD 或纯 SGD。

> **类比**：想象下山找最低点——全批量像每走一步之前，先精确测量整座山谷的坡度再迈步：方向最准，但每次"测量"都要花很久；随机梯度下降像只看脚下这一小块地就直接迈步：走得飞快，但因为局部地形起伏，路线歪歪扭扭，快到谷底时还会一直打转找不准中心；小批量则是看看脚下周围一小片区域的平均坡度再迈步——比只看一个点准，又不用测量整座山，是实践中最常用的折中方案。

### 动量梯度下降（Gradient Descent with Momentum）

**一句话理解**：更新参数时，不是只看"这一步"算出来的梯度，而是把最近若干步的梯度做一个**指数加权平均**（相当于给历史梯度装上"记忆"），用这个平滑过的方向来决定往哪走、走多远——效果就像给参数更新加上了"惯性"（动量），能有效抵消 [mini-batch/SGD](#全批量、随机、小批量梯度下降) 带来的抖动噪声，同时在梯度方向一直保持一致的维度上越冲越快。

#### 先搞懂"指数加权平均"这个基础工具

公式：`v_t = β·v_{t-1} + (1-β)·θ_t`，`β` 是一个 0~1 之间的系数，越接近 1，"记忆"看得越远。

#### 具体例子：为什么动量能"削噪声、加速度"

回顾前面讲[归一化](#数据归一化-normalizing-inputs-让梯度下降走得更快)时提到的场景：代价函数的等高线是狭长椭圆时，梯度下降容易在一个方向反复震荡，同时在另一个方向缓慢前进。假设连续 6 步 mini-batch 算出来的梯度是：

```
w 方向（该稳步前进的方向）：dw = 2, 2, 3, 2, 3, 2        ← 符号一直是正的，方向一致
b 方向（有噪声、来回抖动的方向）：db = 3, -3, 4, -4, 3, -3  ← 符号一直在变
```

取 `β=0.9`，v 初始为 0，逐步计算 `v = 0.9×v_上一步 + 0.1×当前梯度`：

```
w 方向 v_dw：0.2 → 0.38 → 0.642 → 0.778 → 1.000 → 1.100   ← 一路稳步走高
b 方向 v_db：0.3 → -0.03 → 0.373 → -0.064 → 0.242 → -0.082  ← 一直在 0 附近小幅摆动
```

**结果很直观**：w 方向因为每一步符号都一样，历史梯度不断"叠加累积"，v_dw 越滚越大（从 0.2 涨到 1.1，比单步的 2~3 更有推动力）；b 方向因为符号来回翻转，正负相互抵消，v_db 的振幅（约 ±0.1~0.4）比原始梯度（±3~±4）小了一个数量级——噪声被削平了。

#### 更新公式

```
v_dw = β·v_dw + (1-β)·dw
v_db = β·v_db + (1-β)·db

w = w - α·v_dw
b = b - α·v_db
```

`β` 通常取 **0.9**（大致相当于对最近 `1/(1-β)=10` 步梯度做平均）。`β=0` 就完全退化回普通梯度下降，没有动量效果；`β` 太接近 1（比如 0.999）则平均窗口太长（约 1000 步），历史权重占比过大，反应会变得迟钝、跟不上最新趋势。

> **类比**：普通梯度下降像每一步都"从静止开始"——走一步就停、只看当前脚下的坡度重新决定方向；动量法则像一个有惯性的小球从山谷往下滚，滚动方向主要由之前积累的速度决定，当前这一步的坡度只是对速度做微调。遇到局部的小坑洼、噪声抖动，小球凭惯性能直接冲过去而不被带偏；只要一直朝同一个方向下坡，球还会越滚越快。

> **顺带一提：偏差修正（Bias Correction）**——注意到 `v` 是从 0 开始累积的，训练刚开始的几步，因为"历史"还不够多，加权平均会偏向 0、估计偏低（就是上面例子里 v_dw 前几步涨得比较慢的原因）。理论上可以把 `v_t` 除以 `(1-β^t)` 来修正这个冷启动偏差，但因为训练通常要跑几百上千步，这个偏差很快就可以忽略不计，所以实践中（包括很多框架的默认实现）常常直接省略这一步。

> **顺带一提**：动量梯度下降通常搭配 [mini-batch](#全批量、随机、小批量梯度下降) 一起用——正是 mini-batch 因为每次只看一小撮数据而产生的噪声抖动，才需要动量来平滑；它也是更高级优化器（比如 RMSprop、Adam）的基础构件之一。

### RMSprop（Root Mean Square Propagation）

**一句话理解**：跟[动量梯度下降](#动量梯度下降-gradient-descent-with-momentum)一样，都是用最近的历史梯度信息来"改善"每一步的更新，但角度不同——动量是把**梯度本身**做指数加权平均，用来平滑更新的**方向**；RMSprop 是把**梯度的平方**做指数加权平均，用来给每个参数自适应地缩放更新的**步长**：某个方向如果历史上梯度一直很大、抖得很凶，就把这个方向的步长压小；某个方向梯度一直很小、很稳，就相对放大它的步长——让各个方向的更新幅度趋于均衡。

#### 具体例子

沿用动量那节的场景：w 方向坡度平缓但一直稳步前进，b 方向噪声大、来回抖动。这次故意把差距拉大一点，方便看清效果：

```
w 方向（梯度小但很稳）：dw = 1, 1, 1, 1, 1, 1
b 方向（梯度大且来回抖动）：db = 10, -10, 10, -10, 10, -10
```

RMSprop 对**梯度的平方**做指数加权平均（取 `β2=0.9`），注意平方之后正负号消失，只反映"这个方向历史上抖动的幅度有多大"：

```
s_dw：0.1 → 0.19 → 0.271 → 0.344 → 0.410 → 0.469
s_db：10  → 19   → 27.1  → 34.4  → 41.0  → 46.9
```

第 6 步时，`s_dw≈0.469`，`s_db≈46.9`——相差 100 倍（因为 db 比 dw 大 10 倍，平方后就是 100 倍）。

#### 更新公式

```
s_dw = β2·s_dw + (1-β2)·dw²
s_db = β2·s_db + (1-β2)·db²

w = w - α · dw / (√s_dw + ε)
b = b - α · db / (√s_db + ε)
```

`ε`（比如 1e-8）只是为了防止分母算出 0，不影响主要逻辑。代入第 6 步的数字看效果：

```
w 方向：dw/√s_dw = 1 / √0.469  ≈ 1 / 0.68  ≈ 1.46
b 方向：db/√s_db = -10 / √46.9 ≈ -10 / 6.85 ≈ -1.46
```

**神奇的地方**：原始梯度 w 和 b 差了整整 10 倍（1 vs 10），但除以各自的 `√s` 之后，实际的更新幅度变得**几乎一样大**（≈1.46）——RMSprop 把 b 方向那种"大幅抖动"的步长自动压小，把 w 方向那种"温和但持续"的步长相对放大，让两个方向朝着最优点前进的速度更均衡，不会出现 b 方向来回震荡、w 方向却几乎不动的情况。

> **类比**：想象两条路——一条是坑坑洼洼的颠簸路（对应 b 方向，梯度忽大忽小），一条是平坦的直路（对应 w 方向，梯度稳定）。普通梯度下降在颠簸路上开会被路况带着乱晃、时快时慢；RMSprop 相当于给每条路都装了一个"自适应减震器"：颠簸路上自动收着点开（除以一个更大的数），平坦路上可以适度多给点油（除以一个较小的数）——最终两条路都能稳稳当当地开到终点。

> **顺带一提：和动量的关系**——动量解决的是"方向抖不抖"（靠平均梯度本身，正负号会抵消噪声），RMSprop 解决的是"步子大不大"（靠平均梯度平方，自适应缩放步长），两者是互补的两个维度。把这两者结合起来，就是深度学习里最常用的优化器之一——**Adam**（本质上就是"动量 + RMSprop"的组合）。

### Adam（Adaptive Moment Estimation）

**一句话理解**：Adam 就是把[动量梯度下降](#动量梯度下降-gradient-descent-with-momentum)和 [RMSprop](#rmsprop-root-mean-square-propagation) **直接合体**——同时维护两套指数加权平均：一套是梯度本身的均值 `v`（动量，负责平滑方向、抵消噪声抖动），一套是梯度平方的均值 `s`（RMSprop，负责按历史波动幅度自适应缩放步长），更新参数时用 `v` 除以 `√s`——这样"该稳步走的方向大步走，该抖动的方向被压得几乎不动"，两种效果叠加，是目前深度学习里最常用、最省心的默认优化器。

#### 公式

```
v_dw = β1·v_dw + (1-β1)·dw        ← 动量部分（一阶矩，梯度的均值）
s_dw = β2·s_dw + (1-β2)·dw²       ← RMSprop部分（二阶矩，梯度平方的均值）

偏差修正（Adam 里这一步是标配，不像纯动量法常被省略）：
v_dw_corrected = v_dw / (1-β1^t)
s_dw_corrected = s_dw / (1-β2^t)

更新：
w = w - α · v_dw_corrected / (√s_dw_corrected + ε)
```

（`b` 方向公式完全一样，把 `w` 换成 `b` 即可）

#### 具体例子：接着 RMSprop 那节的数字往下算

还是同一个场景：

```
w 方向（梯度小但很稳）：dw = 1, 1, 1, 1, 1, 1
b 方向（梯度大且来回抖动）：db = 10, -10, 10, -10, 10, -10
```

取 `β1=0.9`（动量部分），算出 `v`（这次不取绝对值，正负号照旧参与计算）：

```
v_dw：0.1 → 0.19 → 0.271 → 0.344 → 0.410 → 0.469
v_db：1.0 → -0.1 → 0.91  → -0.181 → 0.837 → -0.247   ← 正负号来回抵消，累积值一直很小
```

`s_dw`、`s_db` 沿用 RMSprop 那节已经算出来的结果（`β2=0.9`）：

```
s_dw：0.469     s_db：46.9
```

第 6 步，做偏差修正（`t=6`，`1-0.9^6=0.4686`）：

```
v_dw_corrected = 0.469/0.4686 ≈ 1.00      s_dw_corrected = 0.469/0.4686 ≈ 1.00
v_db_corrected = -0.247/0.4686 ≈ -0.526   s_db_corrected = 46.9/0.4686 ≈ 100.1
```

代入更新公式（先不看学习率 α）：

```
w 方向：v_dw_corrected/√s_dw_corrected = 1.00/√1.00 ≈ 1.00
b 方向：v_db_corrected/√s_db_corrected = -0.526/√100.1 ≈ -0.053
```

#### 三种方法效果对比（同一个第 6 步）

| | 原始梯度 | 只用 RMSprop | Adam（动量+RMSprop） |
|-|-|-|-|
| w 方向 | 1 | ≈1.46 | ≈1.00 |
| b 方向 | -10 | ≈-1.46 | **≈-0.05** |

**这组数字很说明问题**：原始梯度里 b 比 w 大 10 倍；只用 RMSprop，两者的步长被拉到差不多大（≈1.46），但 b 方向依然每步都在正负跳变、没消停；而 Adam 因为多了动量那部分"先把正负号互相抵消掉"，b 方向的有效更新被压到了几乎为 0（≈-0.05），w 方向则几乎不受影响、照常前进（≈1.00）——噪声方向被压得更彻底，稳定方向的进度几乎没损失。

#### 常用超参数默认值

```
β1 = 0.9      （动量部分，一般不用调）
β2 = 0.999    （RMSprop部分，一般不用调）
ε  = 1e-8     （防止除0，一般不用调）
α  = 需要调   （唯一通常需要花心思调的超参数）
```

> **类比**：动量像给车加了惯性——遇到坑洼不会被带偏；RMSprop 像给每个轮子都装了自适应减震器——颠簸的轮子自动收着开，平稳的轮子可以正常给油。Adam 就是把这两套系统装在同一辆车上——既不容易被单次颠簸带偏方向，每个轮子的力度也会根据路况自动调整，这也是为什么它现在几乎是训练神经网络时的默认选择。

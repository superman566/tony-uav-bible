# PX4 与 Pixhawk 是什么

> **一句话理解：PX4 是飞控软件（大脑里的"思想"），Pixhawk 是飞控硬件（大脑本身）。**

## Part 1：大图景——PX4、Pixhawk、ROS 各管什么

### 打个比方：手机 vs 无人机

| | 手机 | 无人机 |
|---|---|---|
| 硬件 | iPhone 手机 | **Pixhawk** 飞控板 |
| 软件（系统） | iOS 系统 | **PX4** 飞控固件 |

Pixhawk 是一块巴掌大的电路板，PX4 是装在这块板子上运行的程序。只有板子没有程序，它什么也不会做；只有程序没有板子，程序也没地方运行。

### PX4 是什么

PX4 是一套开源的飞控软件（Flight Control Software），负责让无人机飞起来、飞得稳。

它每秒要重复下面这件事几百次：

```
1. 读传感器：我现在向左歪了 5°，高度 10.2 米
2. 和目标比：目标是水平、高度 10 米
3. 算怎么调：左边电机转快一点，整体油门小一点
4. 发给电机执行
```

**举个例子**：一阵风把无人机吹得向左歪了 5°。PX4 发现"实际 5°，目标 0°，差了 5°"，于是让左侧电机加速、右侧电机减速，几十毫秒后机身就被扶正了。人眼看起来，无人机就是一直稳稳地悬停在那里。

除了保持平稳，PX4 还提供各种飞行模式（Flight Mode），比如原地悬停、自动返航、按航线飞等，详见 [PX4 常用飞行模式](#part-3-px4-软件——常用飞行模式-flight-mode)。

### Pixhawk 是什么

Pixhawk 是一个开源的飞控硬件标准（Hardware Standard）。它不是某一家公司的单一产品，而是一套"设计规范"，很多厂家都按这个标准生产飞控板，例如 Holybro 的 Pixhawk 6C、Pixhawk 6X。

板子上具体有什么、各代有什么区别，见 [Part 2：Pixhawk 硬件](#part-2-pixhawk-硬件——板子上有什么)。

### 不是绑死的组合

- PX4 不只能跑在 Pixhawk 上，也支持其他飞控板
- Pixhawk 也不只能跑 PX4，还能装另一套开源飞控软件 **ArduPilot**（后面讲飞行模式时会碰到它和 PX4 的命名差异）

不过 **PX4 + Pixhawk** 是最经典、资料最多的组合，也是本栏目的学习主线。

### 它们和 ROS 的关系

```
机载电脑 + ROS 2   ← "我要去那栋楼，绕开那棵树"（高层决策）
        ↓
Pixhawk + PX4      ← "那我把 4 个电机这样调"（底层控制）
        ↓
电机 / 螺旋桨
```

- **ROS（Robot Operating System，机器人操作系统）**：跑在机载电脑（Companion Computer，如树莓派、Jetson）上，负责"往哪飞、怎么避障、看到了什么"这类聪明的决策
- **PX4**：跑在 Pixhawk 上，负责把"往前飞 1 米"这种指令变成每个电机具体该怎么转，并保证飞行稳定

**类比**：ROS 像出租车上的乘客兼导航，说"去机场，走高速"；PX4 像司机，负责踩油门、打方向盘、保持车道。

## Part 2：Pixhawk 硬件——板子上有什么

### 板子上有什么：处理器 + 传感器 + 接口

> **一句话理解：飞控硬件 = 处理器 + 传感器 + 接口。** 传感器负责"感觉"，处理器负责"思考"，接口负责"传话和动手"。

用[上面被风吹歪的例子](#px4-是什么)，从硬件角度看一遍：

```
传感器（感觉）          处理器（思考）              接口（动手）
IMU：机身左歪了 5°  →  PX4：左边电机转快一点  →  PWM 信号 → 电调 → 左侧电机加速
```

三块缺一不可：没有传感器，飞控不知道自己歪了；没有处理器，知道了也算不出怎么调；没有接口，算出来了也指挥不了电机。


具体到板子上，主要有这些东西：

| 类别 | 部件 | 作用 | 类比 |
|---|---|---|---|
| 处理器 | 处理器（MCU，Microcontroller Unit） | 运行 PX4 程序（详见[处理器一节](#处理器-processor-飞控的-大脑)） | 大脑 |
| 传感器 | 陀螺仪（Gyroscope） | 测机身"转得多快"（详见[陀螺仪一节](#陀螺仪-gyroscope-测机身转得多快)） | 内耳的平衡感 |
| 传感器 | 加速度计（Accelerometer） | 测"往哪个方向加速 / 重力朝哪"（详见[加速度计一节](#加速度计-accelerometer-测加速度和重力方向)） | 坐电梯时感觉到的推力 |
| 传感器 | 气压计（Barometer） | 根据气压估算高度 | 爬山时耳朵发胀 |
| 传感器 | 磁罗盘（Compass / Magnetometer） | 测机头朝向 | 指南针 |
| 接口 | 各种接口 | 接 GPS、电机电调、遥控接收机、数传等（详见[接线图一节](#接线图-pixhawk-6x-怎么连成一架无人机)） | 手脚和神经 |

注意：GPS 一般不在飞控板上，而是一个外接模块，通过接口连到飞控上。

### 处理器（Processor）：飞控的"大脑"

> **一句话理解：以 Pixhawk 6X 为例，主处理器是 STM32H753，核心是 Arm Cortex-M7(/ ˈkɔːteks /)，主频 480 MHz。** 板上其实还有第二颗小处理器（Cortex-M3），专门管输出信号。

#### Cortex-M7 和 STM32H753 是什么关系

Arm 公司只设计处理器**核心（Core）**，不自己造芯片；ST（意法半导体）买下设计，再加上内存、各种接口，做成一颗完整芯片卖出去。

```
Arm 设计的核心      +  ST 加上内存、外设接口  =  完整的芯片
Cortex-M7               Flash、RAM、串口、PWM...    STM32H753
```

打个比方：Cortex-M7 像发动机图纸，STM32H753 是按这张图纸造出来、装好车身和轮子的整辆车。

#### 两颗处理器，各管一摊

| | 主处理器 FMU（Flight Management Unit） | IO 处理器（IO Processor） |
|---|---|---|
| 芯片 | STM32H753 | STM32F103 |
| 核心 | Cortex-M7，480 MHz | Cortex-M3，72 MHz |
| 内存 | 2 MB Flash、1 MB RAM | 64 KB RAM |
| 负责什么 | 运行 PX4：读传感器、估算姿态、算控制量 | 输出 PWM 信号给电调、读遥控器信号 |
| 类比 | 大脑：负责思考 | 脊髓：负责把命令传给手脚 |

分开的好处是：主处理器专心算，IO 处理器专心按时输出信号；万一主处理器出问题，IO 处理器还能做一些保底的安全处理（Failsafe）。

> 补充：还有一个变种 **Pixhawk 6X-RT**，主处理器换成了 NXP 的 i.MX RT1176，核心同样是 Cortex-M7，但主频提到了 1 GHz。

#### 480 MHz 比手机慢很多，够用吗？

先对比一下：

| | Pixhawk 6X 主处理器 | 手机处理器 |
|---|---|---|
| 核心系列 | Cortex-**M**（微控制器，Microcontroller） | Cortex-**A**（应用处理器，Application Processor） |
| 主频 | 480 MHz | 约 3 GHz |
| 内存 | 1 MB | 约 8 GB |
| 跑什么系统 | 实时操作系统 NuttX（RTOS，Real-Time Operating System） | Android / iOS |

看起来差很多，但飞控的任务很"小"，关键是**准时**，而不是算得多。算一笔账：

```
姿态控制循环频率：1000 次/秒  →  每次循环有 1 ms
480 MHz = 每秒 4.8 亿个时钟周期
每次循环可用：480,000,000 ÷ 1000 = 480,000 个时钟周期
```

一次姿态控制计算只需要其中一小部分，时间绰绰有余。

更重要的是 Cortex-M 的特点是**实时性（Real-Time）**：说 1 ms 算完就一定 1 ms 算完。手机偶尔卡顿半秒没什么，飞控如果卡半秒没去扶正机身，飞机可能就翻了。

打个比方：手机处理器像大卡车，装得多但起步慢；Cortex-M7 像摩托车，装不了多少东西，但每次都能准时送到。

> 需要大算力的任务（比如跑 ROS 2、YOLO 目标检测）不放在飞控上，而是交给另外加装的**机载计算机（Companion Computer）**，比如树莓派（Raspberry Pi）或 Jetson，它们用的是 Cortex-A 这类大处理器。分工见前面的[它们和 ROS 的关系](#它们和-ros-的关系)。

### IMU（Inertial/ ɪˈnɜːʃl / Measurement Unit）：飞控最核心的传感器 {#imu-inertial-measurement-unit-飞控最核心的传感器}

> **一句话理解：IMU 就是惯性测量单元（Inertial Measurement Unit），一颗专门测"机身怎么动"的小芯片，里面装着陀螺仪和加速度计。**

```
IMU = 陀螺仪（Gyroscope）       → 测"转得多快"，单位 °/s
    + 加速度计（Accelerometer） → 测"往哪加速、重力朝哪"，单位 m/s²
```

两种传感器各测 X、Y、Z 三个方向，加起来就是常说的 **6 轴 IMU**；有的芯片再加一个磁力计（Magnetometer/ ˌmæɡnɪˈtɒmɪtə(r) /）测 3 个方向的磁场，就叫 **9 轴 IMU**。

打个比方：IMU 就像人的**内耳**。闭着眼睛，你也能感觉到自己在转、在往前冲、身体歪没歪，IMU 替无人机做的就是这件事。

IMU 是飞控里最离不开的传感器：没有 GPS，飞机还能靠 IMU 保持水平（比如 [Stabilized 模式](#手动模式-manual-modes-你飞-px4-帮忙)）；没有 IMU，飞机连站都站不稳。所以：

- **Pixhawk 6X 装了 3 个 IMU**，一个坏了或读数异常，PX4 可以切换到另一个，这叫冗余（Redundancy）
- **IMU 要减震**：电机一转整个机架都在抖，Pixhawk 6X 的核心模块里专门垫了一层减震泡棉（见后面的[拆解图](#各代长什么样-飞控硬件的进化)），就是为了不让抖动干扰 IMU

下面分别看看 IMU 里的两个传感器，再看 PX4 怎么把它们合起来用。

#### 陀螺仪（Gyroscope）：测机身转得多快

> **一句话理解：陀螺仪测的是"整架无人机此刻正以多快的速度在转"，单位是度/秒（°/s）。** 就像闭眼坐在转椅上，看不见也能感觉到"我在转，而且转得挺快"。

它同时测 3 个方向的转动：

| 转动方向 | 无人机上的样子 | 类比 |
|---|---|---|
| 横滚（Roll） | 左右歪 | 飞机摇晃翅膀 |
| 俯仰（Pitch） | 低头 / 抬头 | 点头 |
| 偏航（Yaw） | 原地转圈改变朝向 | 摇头 |

注意它测的是**机身**，不是马达：悬停时 4 个马达飞快地转，但机身不动，陀螺仪读数约等于 0。

陀螺仪不直接告诉你"歪了几度"，PX4 要把"角速度 × 时间"累加起来才能算出角度：

```
每 0.01 秒读一次：+50 °/s，+50 °/s
歪的角度 = 50 × 0.01 + 50 × 0.01 = 1°
```

**缺点：漂移（Drift）**。每次测量都有一点小误差，累加久了就越积越多：

```
假设每秒误差 0.01°，10 分钟后：0.01 × 600 = 6°   ← 实际是平的，它却以为歪了 6°
```

#### 加速度计（Accelerometer）：测加速度和重力方向

> **一句话理解：加速度计测的是"机身正被往哪个方向推、推得多猛"，单位是米/秒²（m/s²）。** 就算机身一动不动，它也能测到重力（约 9.8 m/s²），所以知道哪边是"下"。就像坐电梯，静止时只感觉到体重，突然向上加速时会觉得脚底一沉。

**怎么用重力算角度**：机身歪了，重力就会"分"一部分到侧面：

```
机身右歪 5°：侧面 X = 9.8 × sin5° ≈ 0.85 m/s²，竖直 Z = 9.8 × cos5° ≈ 9.76 m/s²
倾斜角 = arctan(0.85 ÷ 9.76) ≈ 5°
```

重力永远朝下、大小不变，所以这样算出来的角度**不会越积越歪**，正好弥补陀螺仪的漂移。

**缺点：怕震动**。电机一转机架就抖，抖动也会被测进去：

```
震动让 X 多了 2 m/s²：arctan((0.85 + 2) ÷ 9.76) ≈ 16°   ← 实际只歪了 5°
```

#### 两者互补：传感器融合（Sensor Fusion）

陀螺仪和加速度计的优缺点正好相反：

| | 陀螺仪 | 加速度计 |
|---|---|---|
| 优点 | 反应快、读数平滑 | 长期准确，不漂移 |
| 缺点 | 时间一长会跑偏（漂移） | 读数抖动大，受震动影响 |

PX4 把两者的数据融合起来，得到又快又准的姿态。最简单的融合方法叫**互补滤波（Complementary Filter）**，思路是"短期信陀螺仪，长期信加速度计"：

```
新角度 = 0.98 × (上次角度 + 陀螺仪角速度 × Δt) + 0.02 × 加速度计算出的角度
```

**例子 1：加速度计被震动干扰了**

上次角度是 5°，陀螺仪测到机身没在转（0 °/s），加速度计却因为震动算出 16°：

```
新角度 = 0.98 × (5° + 0) + 0.02 × 16°
       = 4.9° + 0.32°
       ≈ 5.2°   ← 加速度计跳了 11°，结果只被带偏 0.2°
```

**例子 2：陀螺仪漂移了**

机身其实是平的（加速度计算出 0°），但陀螺仪累加出来以为歪了 6°。每算一次，结果就被往 0° 拉回一点：

```
第 1 次：0.98 × 6°    + 0.02 × 0° ≈ 5.88°
第 2 次：0.98 × 5.88° + 0.02 × 0° ≈ 5.76°
……
每秒算 100 次，1 秒后：6° × 0.98¹⁰⁰ ≈ 0.8°   ← 漂移很快被纠正回来
```

> PX4 实际用的是更复杂的**扩展卡尔曼滤波器（EKF，Extended Kalman Filter）**，在 PX4 里叫 EKF2，还会把 GPS、气压计、磁力计的数据也融合进来。但核心思路和上面一样：每个传感器取长补短。

### FMU：Pixhawk 的"标准版本号"

> **一句话理解：FMU 是飞行管理单元（Flight Management Unit）的缩写，FMUv6 就是"第 6 代 Pixhawk 硬件标准"。** Pixhawk 6X 遵循的标准叫 **FMUv6X**，Pixhawk 6C 遵循的叫 **FMUv6C**。

#### FMU 的两层意思

| 场景 | FMU 指什么 | 例子 |
|---|---|---|
| 说板子上的芯片 | 运行 PX4 的主处理器 | [处理器一节](#两颗处理器-各管一摊)表格里的"主处理器 FMU" |
| 说硬件标准 | 一整套飞控板的设计规范，加上版本号 | FMUv6X、FMUv6C |

第二种用法更常见。打个比方：**FMUv6X 像 "Wi-Fi 6"，Pixhawk 6X 像某个牌子的 Wi-Fi 6 路由器。** Wi-Fi 6 是标准，很多厂家都能按它造路由器；同理，Holybro 的 Pixhawk 6X、CUAV 的 Pixhawk V6X 都是按 FMUv6X 标准造的，所以能用同一份 PX4 固件。

#### 版本号怎么读

```
FMU   v6       X
 │     │        └─ 同一代里的不同型号：X = 旗舰款，C = 性价比款
 │     └─ 第 6 代标准
 └─ Flight Management Unit，飞行管理单元
```

同一代里，6X 比 6C 更高端：比如 6X 有 3 个 [IMU](#imu-inertial-measurement-unit-飞控最核心的传感器) 互为备份（冗余，Redundancy），还带以太网口（Ethernet）；6C 是 2 个 IMU，价格更便宜。

#### 各代长什么样：飞控硬件的进化

先看一眼整体趋势：

```
外形：  v1 裸电路板 → v2 装进外壳的成品 → v3 核心做成可插拔的方块 → v6X 核心模块 + 底板
处理器：Cortex-M4，168 MHz（v1 ~ v4）→ Cortex-M7，216 MHz（v5）→ Cortex-M7，480 MHz（v6）
```

| 标准 | 代表产品 | 主处理器 | 长什么样 | 这一代的变化 |
|---|---|---|---|---|
| FMUv1 | PX4FMU | Cortex-M4 | ![FMUv1 PX4FMU](/images/fmu/fmuv1_px4fmu.jpg){width=240} | 一块裸露的开发板（Development Board），没有外壳，要再叠一块 PX4IO 板才能接电机 |
| FMUv2 | Pixhawk 1 | STM32F427（Cortex-M4） | ![FMUv2 Pixhawk 1](/images/fmu/fmuv2_pixhawk1.jpg){width=240} | 第一次把主处理器和 IO 处理器装进同一个外壳，成了真正的成品飞控。图为 mRo 版 Pixhawk，外形和原版一样，但 Flash 换成 2 MB，PX4 把它算作 FMUv3 |
| FMUv3 | Hex Cube Black | STM32F427（Cortex-M4） | ![FMUv3 Cube Black](/images/fmu/fmuv3_cube_black.jpg){width=240} | 飞控核心做成一个方块（Cube），插在底板上，坏了可以单独换，是模块化设计的雏形 |
| FMUv4 | Pixracer | STM32F427（Cortex-M4） | ![FMUv4 Pixracer](/images/fmu/fmuv4_pixracer.jpg){width=240} | 体积小，适合小型无人机。图中间那颗大芯片上能看到 `STM32F427` 字样，上面叠着一块 Wi-Fi 模块 |
| FMUv5 | Pixhawk 4 | STM32F765（Cortex-M7） | ![FMUv5 Pixhawk 4](/images/fmu/fmuv5_pixhawk4.jpg){width=200} | 处理器升级到 Cortex-M7（STM32F765）；接口全部印上名字，接线不容易插错 |
| FMUv6C | Pixhawk 6C | STM32H743（Cortex-M7） | ![FMUv6C Pixhawk 6C](/images/fmu/fmuv6c_pixhawk6c.png){width=200} | 外形延续 Pixhawk 4，处理器升级到 STM32H743，480 MHz，定位性价比 |
| FMUv6X | Pixhawk 6X | STM32H753（Cortex-M7） | ![FMUv6X Pixhawk 6X](/images/fmu/fmuv6x_pixhawk6x.png){width=160} | 核心模块 + 底板的模块化设计，3 个 IMU，带以太网口 |

- **下半部分**：底板（Baseboard），上面全是接口：电源、PWM 输出、GPS、数传、USB 等。核心模块通过中间的排线插座插在底板上

#### 在哪里会碰到它：编译和刷固件

最常见的是**编译和刷固件（Firmware）**的时候。PX4 用 FMU 版本号来区分不同的板子：

```bash
# 给 Pixhawk 6X 编译 PX4 固件
make px4_fmu-v6x_default

# 给 Pixhawk 6C 编译
make px4_fmu-v6c_default
```

编译出来的固件文件名也带着它，比如 `px4_fmu-v6x_default.px4`。

**举个例子**：你手上是 Pixhawk 6X，却刷了 `fmu-v6c` 的固件，就像给 Wi-Fi 6 路由器装了别家型号的系统，芯片和传感器对不上，飞控会启动失败或者认不出传感器。用 QGroundControl 刷官方固件时，它会自动识别板子型号；只有自己编译时才需要手动选对。

### 接线图：Pixhawk 6X 怎么连成一架无人机

> **一句话理解：Pixhawk 自己只是"大脑"，要靠一根根线连上电池、GPS、电机、遥控器，才能变成一架能飞的无人机。** 下面这张是 Holybro 官方的 Pixhawk 6X 接线图，可以点开放大看。

![Pixhawk 6X 接线图](/images/pixhawk6x_wiring_diagram.png)

> 图片来源：Holybro 官方文档（docs.holybro.com）。

第一眼看上去线很多，但只要按**用途**分，其实只有 4 类：

```
          ┌─────────── 感知：GPS、激光测距 ───────────┐
          │                                          ↓
电池 → 供电 → 【Pixhawk 6X 大脑】 → 输出：电调 → 电机、舵机
                     ↑↓
          通信：遥控器、数传、机载电脑、USB
```

打个比方，把无人机想成一个人：

| 类别 | 作用 | 类比 | 图中对应 |
|---|---|---|---|
| 供电 | 给所有东西送电 | 心脏和血管 | Battery、Power Module、PDB |
| 感知 | 告诉飞控"我在哪、离地多高" | 眼睛、耳朵 | GPS、Lidar |
| 输出 | 把飞控的命令变成动作 | 手和脚 | ESC、Motor、Servo |
| 通信 | 和外界交流、接收命令 | 嘴和耳朵（对外说话、听指令） | 遥控器、数传、以太网、USB |

图里的线也有规律：**红色 = 正极，黑色 = 负极（地线），黄色 / 白色 = 信号线**。红黑线送"电"，黄线传"话"。

#### 供电：电池的电怎么分出去

看图的左下角和正下方：

```
电池 Battery ─→ 电源模块 PM02D ─┬─→ POWER1 口：给 Pixhawk 供电（降到约 5 V）
                               └─→ 配电板 PDB ─→ 4 个电调 ESC ─→ 4 个电机
```

- **电源模块（Power Module，图中 PM02D）**：像"变压器 + 电表"。一边把电池的高电压降到飞控能用的约 5 V，一边测量电压和电流，告诉 PX4 电池还剩多少电
- **配电板（PDB，Power Distribution Board）**：像家里的**排插**，把电池的电分给 4 个电调

**为什么电机不从飞控取电？** 算一笔账：

```
飞控自己：      不到 1 A（安培）
4 个电机满油门：加起来可能几十 A
```

飞控的接口和细线根本扛不住这么大的电流。所以"大电流"直接从电池经配电板走到电机，飞控只负责发"转多快"的**信号**，不负责送电。就像司机只管踩油门，汽油是从油箱直接送到发动机的，不经过司机的手。

**POWER2 口：备用电源**。可以再接一路电源，POWER1 断了还有 POWER2 顶上，这又是一种冗余（Redundancy）。

#### 感知：GPS 和测距

看图的左上角：

| 图中名字 | 接哪个口 | 作用 |
|---|---|---|
| Primary GPS（M8N） | GPS1 | 主 GPS，告诉飞控"我在地球上哪个位置"。这个圆盘里还集成了**磁罗盘**（测机头朝向）、状态灯、蜂鸣器和安全开关 |
| Secondary GPS（M9N） | GPS2 | 第二个 GPS，和主 GPS 互为备份 |
| ST VL53L1X Lidar | I2C（经 Splitter 分线板） | 激光测距，几米以内精确测"离地多高"，适合低空和降落 |

注意：GPS 是外接模块，不在飞控板上；而 [IMU](#imu-inertial-measurement-unit-飞控最核心的传感器) 和气压计是装在飞控里面的，接线图上看不到。

**一个规律**：Pixhawk 6X 对重要部件基本都"备两份以上"——3 个 IMU、2 个 GPS 口、2 个电源口。一个坏了，另一个马上顶上，飞机不至于掉下来。

#### 输出：从飞控到电机

看图的正下方，飞控底部有两排输出口：

| 接口 | 由谁控制 | 图中接了什么 |
|---|---|---|
| **I/O PWM OUT**（1~8） | [IO 处理器](#两颗处理器-各管一摊)（脊髓） | 1~4 号口 → 4 个电调 → Motor 1~4 |
| **FMU PWM OUT**（1~8） | 主处理器 FMU（大脑） | 舵机（Servo Motor），比如控制云台、投放装置 |

这正好对上[处理器一节](#两颗处理器-各管一摊)讲的"两颗处理器各管一摊"：电机这种最要紧的输出交给 IO 处理器专门负责。

**电调（ESC）** 收到的是 PWM 信号，靠"脉冲有多宽"来表示转多快。常见的约定是：

```
1000 μs（微秒）→ 电机停转
1500 μs        → 大约一半油门
2000 μs        → 满油门
```

PX4 每秒几百次地更新这个数字，比如把 1 号电机从 1500 μs 调到 1550 μs，它就转快一点。

**为什么 4 个电机转向不一样？** 图里 Motor 1、2 标着 CCW（Counter-Clockwise，逆时针），Motor 3、4 标着 CW（Clockwise，顺时针），对角线上的两个转向相同。

- 螺旋桨往一个方向转，机身就会被往反方向"扭"（反扭矩）。就像你坐在转椅上用力甩手臂，身子会往反方向转
- 两个顺时针 + 两个逆时针，扭力正好抵消，机身就不会自己原地打转
- 想让无人机转向（偏航 Yaw），就让顺时针那一对转快一点、逆时针那一对转慢一点，扭力不再平衡，机身就转起来了

**BEC（降压模块）**：舵机需要额外供电，Pixhawk 的输出口只传信号、不供电，所以图中舵机旁边单独接了一个 BEC（Battery Eliminator Circuit），从配电板取电再降压给舵机用。

#### 通信：和外界说话

| 图中名字 | 接哪个口 | 作用 | 类比 |
|---|---|---|---|
| SIYI MK15 遥控器 + 接收机 | RC IN（S.Bus 信号） | 你推摇杆，遥控器无线发给机上接收机，接收机再把指令传给飞控 | 对讲机 |
| DSM RC | DSM RC 口 | 另一种品牌（Spektrum）的接收机专用口，和上面二选一 | 换个牌子的对讲机 |
| Telemetry Radio（数传电台） | TELEM1 | 和地面站（QGC）无线连接，用 MAVLink 协议实时回传高度、电量、位置，也能从地面站下命令 | 飞机和塔台之间的无线电 |
| Ethernet（以太网） | ETH | 高速连接[机载计算机](#它们和-ros-的关系)，跑 ROS 2 时常用 | 网线 |
| TELEM2 / TELEM3 | 串口 | 也能接机载计算机、第二个数传或其他传感器 | 备用电话线 |
| USB Type-C | USB | 插电脑：刷固件、用 QGC 调参数 | 充电线兼数据线 |
| Micro SD 卡 | 卡槽 | 记录飞行日志（Log），炸机后靠它查原因 | 飞机的"黑匣子" |

还有几个口图中没接东西，知道是干嘛的就行：

- **CAN1 / CAN2**：一种抗干扰很强的通信线，可以把多个 CAN 设备（比如 CAN 版 GPS、电调）串在一根线上
- **SPI、ADC & GPIO、UART4 & I2C**：扩展口，留给其他传感器和外设
- **FMU Debug / I/O Debug**：开发者调试用，普通用户用不到

#### 串起来：推一下摇杆，信号走了哪些路

把四类线串起来，看你推一下油门杆时发生了什么：

```
1. 你推油门杆        → SIYI 遥控器无线发出指令
2. 机上接收机收到    → 通过 S.Bus 线送进 RC IN 口
3. PX4 读取指令      → 同时读 IMU、GPS，知道自己现在的姿态和位置
4. PX4 算出结果      → "4 个电机都从 1500 μs 加到 1600 μs"
5. I/O PWM OUT 输出  → 信号沿黄线送到 4 个电调
6. 电调从配电板取电  → 按 1600 μs 驱动电机加速，无人机上升
7. 数传电台          → 把"高度在升、电量还剩 85%"回传给地面站
```

信号（黄线）和电力（红黑线）走的是两条路：**飞控管"说什么"，电池管"出多少力"。**

## Part 3：PX4 软件——常用飞行模式（Flight Mode）

> **一句话理解：飞行模式决定"谁来飞、PX4 帮你管多少"。** 可以分成两大类：**手动模式**（你用遥控器飞，PX4 帮你稳住）和**自动模式**（PX4 自己飞，你只下命令）。

下面以多旋翼为例，按 QGC（QGroundControl，地面站软件）顶部飞行模式下拉菜单里的名字列出来。

### 手动模式（Manual Modes）：你飞，PX4 帮忙

| QGC 显示名 | 中文 | 松开摇杆会怎样 | 需要 GPS | 常用度 |
|---|---|---|---|---|
| **Position** | 定点模式 | 原地悬停，抗风也不飘 | ✅ | ⭐⭐⭐ 最常用 |
| **Altitude** | 定高模式 | 高度不变，但会被风吹着水平漂 | ❌ | ⭐⭐ |
| **Stabilized**（有的版本显示 Manual） | 自稳模式 | 机身回正，但高度、位置都不保持 | ❌ | ⭐⭐ |
| Acro | 特技模式 | 保持当前姿态，连翻转都不帮你回正 | ❌ | ⭐ 穿越机玩家用 |

**记忆方法：从上往下，PX4 帮你保持的东西越来越少。**

```
Position   → 保持：姿态 + 高度 + 水平位置   （最省心）
Altitude   → 保持：姿态 + 高度
Stabilized → 保持：姿态
Acro       → 什么都不保持，只稳住转速      （最难飞）
```

**新手建议**：日常用 **Position**。GPS 信号不好时（比如在室内或楼宇之间）退到 **Altitude**。

### 自动模式（Autonomous Modes）：PX4 自己飞

| QGC 显示名 | 中文 | 做什么 | 常用度 |
|---|---|---|---|
| **Takeoff** | 起飞模式 | 自动起飞到设定高度（默认约 2.5 米），然后悬停 | ⭐⭐⭐ |
| **Land** | 降落模式 | 原地垂直降落，落地后自动上锁 | ⭐⭐⭐ |
| **Return** | 返航模式 | 先升到安全高度，再飞回起飞点降落 | ⭐⭐⭐ 保命用 |
| **Hold** | 保持模式 | 原地悬停等待（内部名 Loiter，见[下文](#hold-mode-与-loiter-的关系)） | ⭐⭐⭐ |
| **Mission** | 任务模式 | 按 QGC 里规划好的航点自动飞 | ⭐⭐⭐ |
| **Offboard** | 外部控制模式 | 听机载电脑（ROS 2）发来的指令 | ⭐⭐⭐ 学 ROS 必用 |
| Orbit | 环绕模式 | 绕一个点转圈，常用于航拍 | ⭐ |
| Follow Me | 跟随模式 | 跟着地面站（手机、平板）移动 | ⭐ |
| Precision Land | 精准降落 | 借助视觉标记精确降落 | ⭐ |

### 一次典型飞行会用到哪些模式

**例子 1：手动练习飞行**

```
解锁 → Position 起飞、练习 → 遇到问题切 Return 返航 → Land 降落
```

**例子 2：自动航线任务**

```
QGC 里画好航点 → Takeoff → Mission 自动飞航线
→ 中途想暂停切 Hold → 再切回 Mission 继续 → 任务结束自动 Return 返航降落
```

**例子 3：ROS 2 控制（本栏目的学习重点）**

```
Takeoff 起飞 → ROS 2 开始持续发指令 → 切 Offboard
→ ROS 程序控制飞行 → 结束后切 Land 降落
```

**注意**：Offboard 要求外部电脑**持续不断地**发送指令（至少每秒 2 次）。一旦断了，PX4 会认为外部电脑掉线，自动触发失控保护（Failsafe），比如切到 Hold 或 Return。这是写 ROS 控制程序时第一个要注意的地方。

### Hold Mode 与 Loiter 的关系

PX4 的 **Hold Mode** 在代码内部叫 `AUTO_LOITER`，所以在日志、MAVLink 消息和一些老教程里会看到 "Loiter" 这个词（英文本意是"徘徊、逗留"）。

- **多旋翼**：原地悬停不动
- **固定翼**：不能悬停，所以绕当前位置盘旋

**例子**：任务飞到一半想暂停，切到 Hold，无人机就停在原地等着；再切回 Mission，它会接着往下飞。

**容易混淆**：[前面提到的](#不是绑死的组合)另一套飞控软件 ArduPilot 也有一个 **Loiter** 模式，但它和 PX4 的 Hold **不是同一个东西**：

| | PX4 Hold | ArduPilot Loiter | PX4 Position |
|---|---|---|---|
| 谁在控制 | 全自动 | 遥控器手动 | 遥控器手动 |
| 推摇杆会怎样 | 不响应（要先切出这个模式） | 跟着摇杆飞 | 跟着摇杆飞 |
| 松开摇杆 | 原地悬停 | 原地悬停 | 原地悬停 |

**一句话总结**：ArduPilot 的 Loiter ≈ PX4 的 Position；PX4 的 Hold 是全自动悬停，内部名字才叫 Loiter。看资料时遇到 "Loiter"，先分清说的是哪一套飞控。

### 总结：先掌握这 8 个

| 用途 | 模式 |
|---|---|
| 手动飞 | **Position**、**Altitude** |
| 起降 | **Takeoff**、**Land** |
| 保命 | **Return**、**Hold** |
| 自动 / 编程 | **Mission**、**Offboard** |

## 术语表

### PX4 {.ignore-header}
开源飞控软件（Flight Control Software），跑在飞控板上，负责读传感器、算控制量、指挥电机，让无人机飞稳。见 [PX4 是什么](#px4-是什么)。

### Pixhawk {.ignore-header}
开源飞控硬件标准（Hardware Standard），很多厂家按它生产飞控板，如 Holybro Pixhawk 6X / 6C。见 [Pixhawk 是什么](#pixhawk-是什么)。

### ArduPilot {.ignore-header}
另一套开源飞控软件，也能跑在 Pixhawk 上。注意它的 Loiter 模式 ≈ PX4 的 Position 模式。见 [Hold Mode 与 Loiter 的关系](#hold-mode-与-loiter-的关系)。

### 机载计算机（Companion Computer） {.ignore-header}
另外加装在无人机上的"大算力"电脑，如树莓派、Jetson，用来跑 ROS 2、YOLO 等。见 [它们和 ROS 的关系](#它们和-ros-的关系)。

### 微控制器（MCU，Microcontroller Unit） {.ignore-header}
飞控板上的处理器芯片，主频低、内存小，但实时性好。Pixhawk 6X 用的是 STM32H753。见 [处理器](#处理器-processor-飞控的-大脑)。

### Cortex-M / Cortex-A {.ignore-header}
Arm 设计的两类处理器核心：Cortex-M 是微控制器（飞控用，讲究准时），Cortex-A 是应用处理器（手机、树莓派用，讲究算力）。见 [480 MHz 够用吗](#_480-mhz-比手机慢很多-够用吗)。

### 实时操作系统（RTOS，Real-Time Operating System） {.ignore-header}
保证"说 1 ms 算完就一定 1 ms 算完"的操作系统。PX4 在 Pixhawk 上跑的是 NuttX。

### FMU（Flight Management Unit） {.ignore-header}
飞行管理单元。既指运行 PX4 的主处理器，也指 Pixhawk 硬件标准的版本号（如 FMUv6X）。见 [FMU](#fmu-pixhawk-的-标准版本号)。

### IO 处理器（IO Processor） {.ignore-header}
Pixhawk 上的第二颗小处理器，专门输出 PWM 信号、读遥控器信号，主处理器出问题时还能做保底处理。见 [两颗处理器，各管一摊](#两颗处理器-各管一摊)。

### 电源模块（Power Module） {.ignore-header}
把电池电压降到飞控能用的约 5 V，同时测电压和电流，让 PX4 知道剩余电量。见 [供电](#供电-电池的电怎么分出去)。

### 配电板（PDB，Power Distribution Board） {.ignore-header}
无人机上的"排插"，把电池的大电流分给各个电调。

### BEC（Battery Eliminator Circuit） {.ignore-header}
降压模块，给舵机等额外设备单独供电。

### 接收机（Receiver）/ S.Bus {.ignore-header}
接收机装在飞机上，接收遥控器的无线指令；S.Bus 是它把指令传给飞控时常用的一种信号格式，一根线就能传多个通道。

### 数传电台（Telemetry Radio） {.ignore-header}
飞机和地面站之间的无线连接，实时回传飞行数据，也能从地面站下命令。

### MAVLink {.ignore-header}
PX4 和地面站、机载计算机之间"对话"用的通信协议（Protocol）。

### 反扭矩（Reaction Torque）/ CW / CCW {.ignore-header}
螺旋桨转动会把机身往反方向扭。四旋翼用 2 个顺时针（CW）+ 2 个逆时针（CCW）电机互相抵消，改变两对的转速差就能转向。见 [输出](#输出-从飞控到电机)。

### 电调（ESC，Electronic Speed Controller） {.ignore-header}
电子调速器，接收飞控发来的 PWM 信号，控制每个马达转多快（RPM）。

### PWM（Pulse Width Modulation） {.ignore-header}
脉冲宽度调制，飞控通过它告诉电调"马达该转多快"。

### IMU（Inertial Measurement Unit） {.ignore-header}
惯性测量单元，内含陀螺仪和加速度计，测"机身怎么动"。见 [IMU](#imu-inertial-measurement-unit-飞控最核心的传感器)。

### 陀螺仪（Gyroscope） {.ignore-header}
测机身转动的角速度（°/s）。反应快，但累加久了会漂移。

### 加速度计（Accelerometer） {.ignore-header}
测加速度和重力方向（m/s²）。长期准确，但怕震动。

### 横滚 / 俯仰 / 偏航（Roll / Pitch / Yaw） {.ignore-header}
机身的三个转动方向：左右歪 / 低头抬头 / 原地转圈。见 [陀螺仪](#陀螺仪-gyroscope-测机身转得多快)。

### 漂移（Drift） {.ignore-header}
陀螺仪的小误差在累加中越积越大，导致"实际是平的，却以为歪了"。

### 传感器融合（Sensor Fusion） {.ignore-header}
把多个传感器的数据合起来、取长补短。最简单的方法是互补滤波（Complementary Filter），PX4 实际用的是 EKF2（扩展卡尔曼滤波器，Extended Kalman Filter）。见 [两者互补](#两者互补-传感器融合-sensor-fusion)。

### 冗余（Redundancy） {.ignore-header}
同一种部件装多份互为备份，如 Pixhawk 6X 的 3 个 IMU，一个坏了还能切到另一个。

### 飞行模式（Flight Mode） {.ignore-header}
决定"谁来飞、PX4 帮你管多少"，分手动模式和自动模式。见 [Part 3](#part-3-px4-软件——常用飞行模式-flight-mode)。

### Offboard 模式 {.ignore-header}
外部控制模式，PX4 听机载计算机（ROS 2）发来的指令飞，要求指令持续不断（至少每秒 2 次）。

### 失控保护（Failsafe） {.ignore-header}
出现异常（如 Offboard 指令中断、遥控信号丢失）时 PX4 自动采取的保护动作，比如切到 Hold 或 Return。

### QGC（QGroundControl） {.ignore-header}
PX4 常用的地面站软件，用来切飞行模式、规划航线、刷固件。

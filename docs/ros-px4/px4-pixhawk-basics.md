# PX4 与 Pixhawk 是什么

> **一句话理解：PX4 是飞控软件（大脑里的"思想"），Pixhawk 是飞控硬件（大脑本身）。**

## 打个比方：手机 vs 无人机

| | 手机 | 无人机 |
|---|---|---|
| 硬件 | iPhone 手机 | **Pixhawk** 飞控板 |
| 软件（系统） | iOS 系统 | **PX4** 飞控固件 |

Pixhawk 是一块巴掌大的电路板，PX4 是装在这块板子上运行的程序。只有板子没有程序，它什么也不会做；只有程序没有板子，程序也没地方运行。

## PX4 是什么

PX4 是一套开源的飞控软件（Flight Control Software），负责让无人机飞起来、飞得稳。

它每秒要重复下面这件事几百次：

```
1. 读传感器：我现在向左歪了 5°，高度 10.2 米
2. 和目标比：目标是水平、高度 10 米
3. 算怎么调：左边电机转快一点，整体油门小一点
4. 发给电机执行
```

**举个例子**：一阵风把无人机吹得向左歪了 5°。PX4 发现"实际 5°，目标 0°，差了 5°"，于是让左侧电机加速、右侧电机减速，几十毫秒后机身就被扶正了。人眼看起来，无人机就是一直稳稳地悬停在那里。

除了保持平稳，PX4 还提供各种飞行模式（Flight Mode），比如原地悬停、自动返航、按航线飞等，详见 [PX4 常用飞行模式](#px4-常用飞行模式-flight-mode)。

## Pixhawk 是什么

> **一句话理解：飞控硬件 = 处理器 + 传感器 + 接口。** 传感器负责"感觉"，处理器负责"思考"，接口负责"传话和动手"。

用[上面被风吹歪的例子](#px4-是什么)，从硬件角度看一遍：

```
传感器（感觉）          处理器（思考）              接口（动手）
IMU：机身左歪了 5°  →  PX4：左边电机转快一点  →  PWM 信号 → 电调 → 左侧电机加速
```

三块缺一不可：没有传感器，飞控不知道自己歪了；没有处理器，知道了也算不出怎么调；没有接口，算出来了也指挥不了电机。

Pixhawk 是一个开源的飞控硬件标准（Hardware Standard）。它不是某一家公司的单一产品，而是一套"设计规范"，很多厂家都按这个标准生产飞控板，例如 Holybro 的 Pixhawk 6C、Pixhawk 6X。

板子上主要有这些东西：

| 类别 | 部件 | 作用 | 类比 |
|---|---|---|---|
| 处理器 | 处理器（MCU，Microcontroller Unit） | 运行 PX4 程序（详见[处理器一节](#处理器-processor-pixhawk-6x-用的是-cortex-m7)） | 大脑 |
| 传感器 | 陀螺仪（Gyroscope） | 测机身"转得多快"（详见[陀螺仪一节](#陀螺仪-gyroscope-测机身转得多快)） | 内耳的平衡感 |
| 传感器 | 加速度计（Accelerometer） | 测"往哪个方向加速 / 重力朝哪"（详见[加速度计一节](#加速度计-accelerometer-测加速度和重力方向)） | 坐电梯时感觉到的推力 |
| 传感器 | 气压计（Barometer） | 根据气压估算高度 | 爬山时耳朵发胀 |
| 传感器 | 磁罗盘（Compass / Magnetometer） | 测机头朝向 | 指南针 |
| 接口 | 各种接口 | 接 GPS、电机电调、遥控接收机、数传等 | 手脚和神经 |

注意：GPS 一般不在飞控板上，而是一个外接模块，通过接口连到飞控上。

## 处理器（Processor）：Pixhawk 6X 用的是 Cortex-M7

> **一句话理解：是的，Pixhawk 6X 的主处理器是 STM32H753，核心是 Arm Cortex-M7(/ ˈkɔːteks /)，主频 480 MHz。** 板上其实还有第二颗小处理器（Cortex-M3），专门管输出信号。

### Cortex-M7 和 STM32H753 是什么关系

Arm 公司只设计处理器**核心（Core）**，不自己造芯片；ST（意法半导体）买下设计，再加上内存、各种接口，做成一颗完整芯片卖出去。

```
Arm 设计的核心      +  ST 加上内存、外设接口  =  完整的芯片
Cortex-M7               Flash、RAM、串口、PWM...    STM32H753
```

打个比方：Cortex-M7 像发动机图纸，STM32H753 是按这张图纸造出来、装好车身和轮子的整辆车。

### 两颗处理器，各管一摊

| | 主处理器 FMU（Flight Management Unit） | IO 处理器（IO Processor） |
|---|---|---|
| 芯片 | STM32H753 | STM32F103 |
| 核心 | Cortex-M7，480 MHz | Cortex-M3，72 MHz |
| 内存 | 2 MB Flash、1 MB RAM | 64 KB RAM |
| 负责什么 | 运行 PX4：读传感器、估算姿态、算控制量 | 输出 PWM 信号给电调、读遥控器信号 |
| 类比 | 大脑：负责思考 | 脊髓：负责把命令传给手脚 |

分开的好处是：主处理器专心算，IO 处理器专心按时输出信号；万一主处理器出问题，IO 处理器还能做一些保底的安全处理（Failsafe）。

> 补充：还有一个变种 **Pixhawk 6X-RT**，主处理器换成了 NXP 的 i.MX RT1176，核心同样是 Cortex-M7，但主频提到了 1 GHz。

### 480 MHz 比手机慢很多，够用吗？

先对比一下：

| | Pixhawk 6X 主处理器 | 手机处理器 |
|---|---|---|
| 核心系列 | Cortex-**M**（微控制器，Microcontroller） | Cortex-**A**（应用处理器，Application Processor） |
| 主频 | 480 MHz | 约 3 GHz |
| 内存 | 1 MB | 约 8 GB |
| 跑什么系统 | 实时操作系统 NuttX（RTOS，Real-Time Operating System） | Android / iOS |

看起来差很多，但飞控的任务很"小"，关键是**准时**，而不是算得多。算一笔账：

```
姿态控制循环频率：1000 次/秒  →  每次循环有 1 ms
480 MHz = 每秒 4.8 亿个时钟周期
每次循环可用：480,000,000 ÷ 1000 = 480,000 个时钟周期
```

一次姿态控制计算只需要其中一小部分，时间绰绰有余。

更重要的是 Cortex-M 的特点是**实时性（Real-Time）**：说 1 ms 算完就一定 1 ms 算完。手机偶尔卡顿半秒没什么，飞控如果卡半秒没去扶正机身，飞机可能就翻了。

打个比方：手机处理器像大卡车，装得多但起步慢；Cortex-M7 像摩托车，装不了多少东西，但每次都能准时送到。

> 需要大算力的任务（比如跑 ROS 2、YOLO 目标检测）不放在飞控上，而是交给另外加装的**机载计算机（Companion Computer）**，比如树莓派（Raspberry Pi）或 Jetson，它们用的是 Cortex-A 这类大处理器。详见[它们和 ROS 的关系](#它们和-ros-的关系)。

## FMU：Pixhawk 的"标准版本号"

> **一句话理解：FMU 是飞行管理单元（Flight Management Unit）的缩写，FMUv6 就是"第 6 代 Pixhawk 硬件标准"。** Pixhawk 6X 遵循的标准叫 **FMUv6X**，Pixhawk 6C 遵循的叫 **FMUv6C**。

### FMU 的两层意思

| 场景 | FMU 指什么 | 例子 |
|---|---|---|
| 说板子上的芯片 | 运行 PX4 的主处理器 | [上一节](#两颗处理器-各管一摊)表格里的"主处理器 FMU" |
| 说硬件标准 | 一整套飞控板的设计规范，加上版本号 | FMUv6X、FMUv6C |

第二种用法更常见。打个比方：**FMUv6X 像 "Wi-Fi 6"，Pixhawk 6X 像某个牌子的 Wi-Fi 6 路由器。** Wi-Fi 6 是标准，很多厂家都能按它造路由器；同理，Holybro 的 Pixhawk 6X、CUAV 的 Pixhawk V6X 都是按 FMUv6X 标准造的，所以能用同一份 PX4 固件。

### 版本号怎么读

```
FMU   v6       X
 │     │        └─ 同一代里的不同型号：X = 旗舰款，C = 性价比款
 │     └─ 第 6 代标准
 └─ Flight Management Unit，飞行管理单元
```

几代标准和对应的代表产品：

| 标准 | 代表产品 | 主处理器 |
|---|---|---|
| FMUv2 | Pixhawk 1 | STM32F427（Cortex-M4） |
| FMUv5 | Pixhawk 4 | STM32F765（Cortex-M7） |
| FMUv5X | Pixhawk 5X | STM32F765（Cortex-M7） |
| FMUv6C | Pixhawk 6C | STM32H743（Cortex-M7） |
| FMUv6X | Pixhawk 6X | STM32H753（Cortex-M7） |

同一代里，6X 比 6C 更高端：比如 6X 有 3 个 [IMU](#imu-inertial-measurement-unit-飞控最核心的传感器) 互为备份（冗余，Redundancy），还带以太网口（Ethernet）；6C 是 2 个 IMU，价格更便宜。

先看一眼整体趋势：

```
外形：  v1 裸电路板 → v2 装进外壳的成品 → v3 核心做成可插拔的方块 → v6X 核心模块 + 底板
处理器：Cortex-M4，168 MHz（v1 ~ v4）→ Cortex-M7，216 MHz（v5）→ Cortex-M7，480 MHz（v6）
```

### 在哪里会碰到它

最常见的是**编译和刷固件（Firmware）**的时候。PX4 用 FMU 版本号来区分不同的板子：

```bash
# 给 Pixhawk 6X 编译 PX4 固件
make px4_fmu-v6x_default

# 给 Pixhawk 6C 编译
make px4_fmu-v6c_default
```

编译出来的固件文件名也带着它，比如 `px4_fmu-v6x_default.px4`。

**举个例子**：你手上是 Pixhawk 6X，却刷了 `fmu-v6c` 的固件，就像给 Wi-Fi 6 路由器装了别家型号的系统，芯片和传感器对不上，飞控会启动失败或者认不出传感器。用 QGroundControl 刷官方固件时，它会自动识别板子型号；只有自己编译时才需要手动选对。

## IMU（Inertial Measurement Unit）：飞控最核心的传感器

> **一句话理解：IMU 就是惯性测量单元（Inertial Measurement Unit），一颗专门测"机身怎么动"的小芯片，里面装着陀螺仪和加速度计。**

```
IMU = 陀螺仪（Gyroscope）       → 测"转得多快"，单位 °/s
    + 加速度计（Accelerometer） → 测"往哪加速、重力朝哪"，单位 m/s²
```

两种传感器各测 X、Y、Z 三个方向，加起来就是常说的 **6 轴 IMU**；有的芯片再加一个磁力计（Magnetometer）测 3 个方向的磁场，就叫 **9 轴 IMU**。

打个比方：IMU 就像人的**内耳**。闭着眼睛，你也能感觉到自己在转、在往前冲、身体歪没歪，IMU 替无人机做的就是这件事。

IMU 是飞控里最离不开的传感器：没有 GPS，飞机还能靠 IMU 保持水平（比如 [Stabilized 模式](#手动模式-manual-modes-你飞-px4-帮忙)）；没有 IMU，飞机连站都站不稳。所以：

- **Pixhawk 6X 装了 3 个 IMU**，一个坏了或读数异常，PX4 可以切换到另一个，这叫冗余（Redundancy）
- **IMU 要减震**：电机一转整个机架都在抖，[Pixhawk 6X 拆解图](#各代长什么样-飞控硬件的进化)里那层减震泡棉，就是为了不让抖动干扰 IMU

下面分别看看 IMU 里的两个传感器，再看 PX4 怎么把它们合起来用。

### 陀螺仪（Gyroscope）：测机身转得多快

> **一句话理解：陀螺仪测的是"整架无人机此刻正以多快的速度在转"，单位是度/秒（°/s）。** 它不直接告诉你"现在歪了几度"，只告诉你"正在转多快"。

#### 生活例子：闭眼坐转椅

你闭着眼坐在转椅上，有人推了你一下：

- 眼睛看不见，但你能感觉到"我在转，而且转得挺快"，这就是陀螺仪在做的事
- 转椅停下后，你就感觉不到转动了，陀螺仪的读数也会回到 0

人能感觉到转动，靠的是内耳里的半规管，可以理解为人体自带的陀螺仪。

#### 测的是机身，不是马达

陀螺仪是焊在 Pixhawk 飞控板上的一颗小芯片，而飞控板是固定在机架上的：

```
陀螺仪芯片 → 焊在 Pixhawk 板上 → Pixhawk 固定在机架上
```

所以机身怎么转，陀螺仪就跟着怎么转，它测到的就是**整架无人机的转动速度**。

**类比**：手机里也有陀螺仪。你把手机横过来，屏幕会自动旋转，因为手机测到了"我自己被转了 90°"，测的不是手机里的哪个零件。

马达（螺旋桨）的转速由另一个部件负责：**电调（ESC，Electronic Speed Controller，电子调速器）**。

| | 陀螺仪 | 电调 |
|---|---|---|
| 关心谁 | 整架无人机 | 每个马达 |
| 测 / 管什么 | 机身每秒转了几度（°/s） | 马达每分钟转几圈（RPM，Revolutions Per Minute） |
| 悬停时的典型数字 | 约 0 °/s（机身不动） | 每个马达约 5000~10000 RPM |

注意悬停时的反差：4 个马达都在飞快地转，**但机身是静止的，所以陀螺仪读数约等于 0**。

#### 三个转动方向

陀螺仪同时测 3 个方向的转动：

| 转动方向 | 无人机上的样子 | 生活类比 |
|---|---|---|
| 横滚（Roll） | 绕机身前后轴转，左右歪 | 飞机左右摇晃翅膀 |
| 俯仰（Pitch） | 绕机身左右轴转，低头 / 抬头 | 点头 |
| 偏航（Yaw） | 绕竖直轴转，原地转圈改变朝向 | 摇头 |

#### 数字例子：被风吹歪后如何扶正

一阵风吹来，陀螺仪每 0.01 秒报一次数：

```
时间      横滚角速度
0.00 s    0 °/s      ← 平稳
0.01 s    +50 °/s    ← 被风吹，开始向右歪
0.02 s    +50 °/s
0.03 s    0 °/s      ← 不再继续歪了
```

PX4 把"角速度 × 时间"累加起来，就能算出歪了多少：

```
歪的角度 = Σ(角速度 × 时间间隔)
         = 50 °/s × 0.01 s + 50 °/s × 0.01 s
         = 0.5° + 0.5°
         = 1°
```

整个扶正过程是陀螺仪、PX4、电调三者配合完成的：

```
1. 陀螺仪：机身正在向右歪，横滚角速度 +50 °/s   ← 测机身
2. PX4：要往回扶正，让右边马达加速
3. 电调：把右边马达从 8000 RPM 提到 8500 RPM    ← 管马达
4. 陀螺仪：机身不再向右转，读数回到 0 °/s
```

**一句话总结：陀螺仪看机身转了没有，电调管马达转多快，PX4 根据前者决定后者。**

#### 缺点：漂移（Drift）

陀螺仪每次测量都有一点小误差。靠累加来算角度，误差就会越积越多：

```
假设每秒误差 0.01°
1 分钟后：0.01 × 60  = 0.6°
10 分钟后：0.01 × 600 = 6°   ← 实际是平的，它却以为歪了 6°
```

所以 PX4 不会只用陀螺仪，还要靠下面的加速度计来校正。

### 加速度计（Accelerometer）：测加速度和重力方向

> **一句话理解：加速度计测的是"机身正被往哪个方向推、推得多猛"，单位是米/秒²（m/s²）。** 就算机身一动不动，它也能测到重力，所以能知道哪边是"下"。

#### 生活例子：坐电梯

你站在电梯里：

- 电梯静止时，你只感觉到自己的体重，这就是重力
- 电梯突然向上加速，你会觉得脚底一沉、身体变重了，这就是加速度
- 电梯匀速运行后，那种变重的感觉又消失了

加速度计的读数也是这样变的：

```
电梯静止：        读数 ≈ 9.8 m/s²            ← 只有重力
向上加速 2 m/s²： 读数 ≈ 9.8 + 2 = 11.8 m/s² ← 重力 + 加速度
匀速上升：        读数 ≈ 9.8 m/s²            ← 又只剩重力
```

#### 数字例子：用重力算出歪了几度

加速度计同样测 X、Y、Z 三个方向。无人机悬停时，它主要测到的就是重力（约 9.8 m/s²），重力在各个方向上分到多少，取决于机身歪了多少：

```
机身放平：  X 方向 = 0，         Z 方向 = 9.8 m/s²   ← 重力全落在 Z 上
机身右歪 5°：X 方向 = 9.8 × sin5° ≈ 0.85 m/s²
            Z 方向 = 9.8 × cos5° ≈ 9.76 m/s²
```

反过来，PX4 拿到两个读数就能算出倾斜角度：

```
倾斜角 = arctan(X 方向 ÷ Z 方向)
       = arctan(0.85 ÷ 9.76)
       = arctan(0.087)
       ≈ 5°
```

重力永远朝下、永远是 9.8 m/s²，所以这样算出来的角度**不会越积越歪**，这正是陀螺仪做不到的。

#### 缺点：怕震动

电机和螺旋桨一转，整个机架都在高频抖动，加速度计会把这些抖动也一起测进去。假设震动让 X 方向的读数多了 2 m/s²：

```
倾斜角 = arctan((0.85 + 2) ÷ 9.76)
       = arctan(0.292)
       ≈ 16°   ← 实际只歪了 5°，这一瞬间却算成了 16°
```

所以单看加速度计，算出来的角度会一跳一跳的。这也是 IMU 要做减震的原因。

### 两者互补：传感器融合（Sensor Fusion）

陀螺仪和加速度计的优缺点正好相反：

| | 陀螺仪 | 加速度计 |
|---|---|---|
| 优点 | 反应快、读数平滑 | 长期准确，不漂移 |
| 缺点 | 时间一长会跑偏（漂移） | 读数抖动大，受震动影响 |

PX4 把两者的数据融合起来，得到又快又准的姿态。最简单的融合方法叫**互补滤波（Complementary Filter）**，思路是"短期信陀螺仪，长期信加速度计"：

```
新角度 = 0.98 × (上次角度 + 陀螺仪角速度 × Δt) + 0.02 × 加速度计算出的角度
```

**例子 1：加速度计被震动干扰了**

上次角度是 5°，陀螺仪测到机身没在转（0 °/s），加速度计却因为震动算出 16°：

```
新角度 = 0.98 × (5° + 0) + 0.02 × 16°
       = 4.9° + 0.32°
       ≈ 5.2°   ← 加速度计跳了 11°，结果只被带偏 0.2°
```

**例子 2：陀螺仪漂移了**

机身其实是平的（加速度计算出 0°），但陀螺仪累加出来以为歪了 6°。每算一次，结果就被往 0° 拉回一点：

```
第 1 次：0.98 × 6°    + 0.02 × 0° ≈ 5.88°
第 2 次：0.98 × 5.88° + 0.02 × 0° ≈ 5.76°
……
每秒算 100 次，1 秒后：6° × 0.98¹⁰⁰ ≈ 0.8°   ← 漂移很快被纠正回来
```

> PX4 实际用的是更复杂的**扩展卡尔曼滤波器（EKF，Extended Kalman Filter）**，在 PX4 里叫 EKF2，还会把 GPS、气压计、磁力计的数据也融合进来。但核心思路和上面一样：每个传感器取长补短。

## PX4 常用飞行模式（Flight Mode）

> **一句话理解：飞行模式决定"谁来飞、PX4 帮你管多少"。** 可以分成两大类：**手动模式**（你用遥控器飞，PX4 帮你稳住）和**自动模式**（PX4 自己飞，你只下命令）。

下面以多旋翼为例，按 QGC（QGroundControl，地面站软件）顶部飞行模式下拉菜单里的名字列出来。

### 手动模式（Manual Modes）：你飞，PX4 帮忙

| QGC 显示名 | 中文 | 松开摇杆会怎样 | 需要 GPS | 常用度 |
|---|---|---|---|---|
| **Position** | 定点模式 | 原地悬停，抗风也不飘 | ✅ | ⭐⭐⭐ 最常用 |
| **Altitude** | 定高模式 | 高度不变，但会被风吹着水平漂 | ❌ | ⭐⭐ |
| **Stabilized**（有的版本显示 Manual） | 自稳模式 | 机身回正，但高度、位置都不保持 | ❌ | ⭐⭐ |
| Acro | 特技模式 | 保持当前姿态，连翻转都不帮你回正 | ❌ | ⭐ 穿越机玩家用 |

**记忆方法：从上往下，PX4 帮你保持的东西越来越少。**

```
Position   → 保持：姿态 + 高度 + 水平位置   （最省心）
Altitude   → 保持：姿态 + 高度
Stabilized → 保持：姿态
Acro       → 什么都不保持，只稳住转速      （最难飞）
```

**新手建议**：日常用 **Position**。GPS 信号不好时（比如在室内或楼宇之间）退到 **Altitude**。

### 自动模式（Autonomous Modes）：PX4 自己飞

| QGC 显示名 | 中文 | 做什么 | 常用度 |
|---|---|---|---|
| **Takeoff** | 起飞模式 | 自动起飞到设定高度（默认约 2.5 米），然后悬停 | ⭐⭐⭐ |
| **Land** | 降落模式 | 原地垂直降落，落地后自动上锁 | ⭐⭐⭐ |
| **Return** | 返航模式 | 先升到安全高度，再飞回起飞点降落 | ⭐⭐⭐ 保命用 |
| **Hold** | 保持模式 | 原地悬停等待（内部名 Loiter，见[下文](#hold-mode-与-loiter-的关系)） | ⭐⭐⭐ |
| **Mission** | 任务模式 | 按 QGC 里规划好的航点自动飞 | ⭐⭐⭐ |
| **Offboard** | 外部控制模式 | 听机载电脑（ROS 2）发来的指令 | ⭐⭐⭐ 学 ROS 必用 |
| Orbit | 环绕模式 | 绕一个点转圈，常用于航拍 | ⭐ |
| Follow Me | 跟随模式 | 跟着地面站（手机、平板）移动 | ⭐ |
| Precision Land | 精准降落 | 借助视觉标记精确降落 | ⭐ |

### Hold Mode 与 Loiter 的关系

PX4 的 **Hold Mode** 在代码内部叫 `AUTO_LOITER`，所以在日志、MAVLink 消息和一些老教程里会看到 "Loiter" 这个词（英文本意是"徘徊、逗留"）。

- **多旋翼**：原地悬停不动
- **固定翼**：不能悬停，所以绕当前位置盘旋

**例子**：任务飞到一半想暂停，切到 Hold，无人机就停在原地等着；再切回 Mission，它会接着往下飞。

**容易混淆**：另一套飞控软件 ArduPilot 也有一个 **Loiter** 模式，但它和 PX4 的 Hold **不是同一个东西**：

| | PX4 Hold | ArduPilot Loiter | PX4 Position |
|---|---|---|---|
| 谁在控制 | 全自动 | 遥控器手动 | 遥控器手动 |
| 推摇杆会怎样 | 不响应（要先切出这个模式） | 跟着摇杆飞 | 跟着摇杆飞 |
| 松开摇杆 | 原地悬停 | 原地悬停 | 原地悬停 |

**一句话总结**：ArduPilot 的 Loiter ≈ PX4 的 Position；PX4 的 Hold 是全自动悬停，内部名字才叫 Loiter。看资料时遇到 "Loiter"，先分清说的是哪一套飞控。

### 一次典型飞行会用到哪些模式

**例子 1：手动练习飞行**

```
解锁 → Position 起飞、练习 → 遇到问题切 Return 返航 → Land 降落
```

**例子 2：自动航线任务**

```
QGC 里画好航点 → Takeoff → Mission 自动飞航线
→ 中途想暂停切 Hold → 再切回 Mission 继续 → 任务结束自动 Return 返航降落
```

**例子 3：ROS 2 控制（本栏目的学习重点）**

```
Takeoff 起飞 → ROS 2 开始持续发指令 → 切 Offboard
→ ROS 程序控制飞行 → 结束后切 Land 降落
```

**注意**：Offboard 要求外部电脑**持续不断地**发送指令（至少每秒 2 次）。一旦断了，PX4 会认为外部电脑掉线，自动触发失控保护（Failsafe），比如切到 Hold 或 Return。这是写 ROS 控制程序时第一个要注意的地方。

### 总结：先掌握这 8 个

| 用途 | 模式 |
|---|---|
| 手动飞 | **Position**、**Altitude** |
| 起降 | **Takeoff**、**Land** |
| 保命 | **Return**、**Hold** |
| 自动 / 编程 | **Mission**、**Offboard** |

## 它们和 ROS 的关系

```
机载电脑 + ROS 2   ← "我要去那栋楼，绕开那棵树"（高层决策）
        ↓
Pixhawk + PX4      ← "那我把 4 个电机这样调"（底层控制）
        ↓
电机 / 螺旋桨
```

- **ROS（Robot Operating System，机器人操作系统）**：跑在机载电脑（Companion Computer，如树莓派、Jetson）上，负责"往哪飞、怎么避障、看到了什么"这类聪明的决策
- **PX4**：跑在 Pixhawk 上，负责把"往前飞 1 米"这种指令变成每个电机具体该怎么转，并保证飞行稳定

**类比**：ROS 像出租车上的乘客兼导航，说"去机场，走高速"；PX4 像司机，负责踩油门、打方向盘、保持车道。

## 补充：不是绑死的组合

- PX4 不只能跑在 Pixhawk 上，也支持其他飞控板
- Pixhawk 也不只能跑 PX4，还能装另一套开源飞控软件 **ArduPilot**

不过 **PX4 + Pixhawk** 是最经典、资料最多的组合，也是本栏目的学习主线。
